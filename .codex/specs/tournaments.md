# ทัวร์นาเมนต์แบด — จากก๊วนประจำ ไปเจอก๊วนอื่น

## Problem

ก๊วนแบดประจำมีเพดานของตัวเอง เล่นกับคนกลุ่มเดิมทุกสัปดาห์ ฝีมือนิ่ง และไม่รู้ว่า
ตัวเองอยู่ตรงไหนเมื่อเทียบกับก๊วนอื่น

คนที่อยากลองของจริงต้องไปหาทัวร์นาเมนต์เอง ซึ่งทุกวันนี้กระจายอยู่ในเพจเฟซบุ๊ก
กลุ่มไลน์ และป้ายที่สนาม การจัดเองยิ่งยาก — ต้องหาสนามหลายคอร์ตพร้อมกัน
หาก๊วนอื่นมาลง เก็บเงินหลายก๊วน แล้วยังต้องคุมตารางแข่งวันงาน

นี่คือปัญหาเดียวกับที่โปรดักต์นี้แก้อยู่แล้ว แค่ใหญ่ขึ้นหนึ่งระดับ:
**จากคนหลายคนในก๊วนเดียว เป็นก๊วนหลายก๊วนในงานเดียว**

## Flow ที่ต้องการ

```
ตีแบตกับก๊วนประจำอยู่แล้ว
        ↓
อยากท้าทายตัวเอง
        ↓
สร้างทัวร์นาเมนต์ · จองสนาม (วัน เวลา คอร์ตกี่คอร์ต)
        ↓
ต้องการอีก 3 ก๊วนมาแจม (ขั้นต่ำ 2 ทีม)
        ↓
ถึงวันแข่ง มาที่สนาม ทวนกติกา เริ่มแข่ง
        ↓
เพิ่มเพื่อนจากก๊วนอื่น · ประเมินความสามารถ
        ↓
ครั้งหน้าเห็นคะแนนเฉลี่ยของแต่ละก๊วน และคะแนนรายคน
        ↓
เลือกได้ว่าจะลงทัวร์นาเมนต์ระดับไหน
```

## สิ่งที่ระบบยังไม่มีเลย — ตรวจกับฐานข้อมูลจริงแล้ว

นี่ไม่ใช่ฟีเจอร์เดียว flow ข้างบนพึ่งของหกอย่างที่ **ไม่มีอยู่ในระบบแม้แต่อย่างเดียว**

| สิ่งที่ flow สมมติว่ามี | ความจริงวันนี้ |
| --- | --- |
| **ก๊วนที่คงอยู่ข้ามครั้ง** | **ไม่มี** — `sessions` หนึ่งแถวคือการนัดเล่น *หนึ่งครั้ง* ไม่มีคอลัมน์หรือตารางไหนผูกครั้งนี้กับครั้งหน้าเลย |
| ทัวร์นาเมนต์ | ไม่มีตาราง |
| ทีมที่ลงแข่ง | ไม่มีตาราง |
| ผลการแข่งรายแมตช์ | ไม่มีตาราง |
| คะแนนฝีมือ | ไม่มี · `player_credit` มีอยู่จริงแต่เป็น**คะแนนความน่าเชื่อถือเรื่องจ่ายเงิน** คนละเรื่องกันสิ้นเชิง |
| เพื่อน | ไม่มี · `profile_contacts` เก็บแค่เบอร์ / LINE ID / อีเมล ไม่ใช่ความสัมพันธ์ระหว่างคน |

**ข้อแรกคือข้อที่ใหญ่ที่สุด และมันอยู่ก่อนทัวร์นาเมนต์** ถ้าก๊วนไม่คงอยู่
"คะแนนเฉลี่ยของก๊วน" ก็ไม่มีเจ้าของ และ "ชวนอีก 3 ก๊วน" ก็ไม่มีอะไรให้ชวน

### ปัญหาคำศัพท์ที่ต้องแก้ก่อน

ทุกวันนี้ UI เรียก `sessions` ว่า **"ก๊วน"** ("ก๊วนแบดเย็นวันพุธ") แต่ flow นี้ใช้คำว่า
ก๊วนหมายถึง *กลุ่มคน* ที่เล่นด้วยกันประจำ ถ้าเพิ่มของใหม่โดยไม่แก้คำ จะมีคำว่าก๊วน
สองความหมายในแอปเดียว

**เสนอ:** ก๊วน = กลุ่มคนที่คงอยู่ · การนัดเล่นครั้งหนึ่ง = **"นัด"**
เป็นการเปลี่ยนคำทั่วทั้งแอป ต้องทำเป็นตั๋วของตัวเองก่อน ไม่ใช่แถมมากับทัวร์นาเมนต์

---

## สิ่งที่ใช้ของเดิมได้เลย

ทัวร์นาเมนต์ไม่ได้เริ่มจากศูนย์ กลไกหัวใจของโปรดักต์ใช้ซ้ำได้ทั้งก้อน

**ประตูสองบานกลายเป็นประตูสามบาน** — ทุกวันนี้ก๊วนจะเดินหน้าได้ต้องครบทั้ง
*คน* และ *เงิน* ทัวร์นาเมนต์คือรูปเดียวกันสูงขึ้นหนึ่งชั้น: ครบทั้ง **ทีม · เงิน · คอร์ต**
ถ้าทีมไม่ถึงขั้นต่ำภายในกำหนด **คืนเงินเต็มทุกก๊วน** เหมือนที่ก๊วนทำอยู่แล้ว

นี่คือเหตุผลที่ฟีเจอร์นี้เข้ากับโปรดักต์นี้จริง ไม่ใช่ของที่แปะเพิ่ม

| ของเดิม | ใช้กับทัวร์นาเมนต์ยังไง |
| --- | --- |
| การพักเงินและคืนเต็มเมื่อไม่ครบ | ค่าสมัครของแต่ละก๊วนถูกพักไว้ ไม่ครบทีม คืนเต็ม |
| `venues` · `courts` · `bookings` | จองหลายคอร์ตในช่วงเวลาเดียว |
| LSN-0025 ผู้จัดยืนยันคอร์ตเอง | ผู้จัดทัวร์เหมาคอร์ตเองแล้วกดยืนยัน — ทางเดียวกัน |
| LSN-0024 รายการเก็บเงินเพิ่ม | ค่าลูกที่ใช้จริงในวันแข่ง หารตามก๊วน |
| ลิงก์เดียวแชร์เข้า LINE | ใช้ชวนก๊วนอื่นได้ทันที ไม่ต้องสร้างช่องทางใหม่ |
| realtime | ตารางแข่งและผลอัปเดตสดวันงาน |

## เรื่องที่อันตรายที่สุด: คะแนนฝีมือ

flow บอกว่า **ให้คนประเมินความสามารถกันเอง** แล้วเอาคะแนนนั้นมา
**กำหนดว่าใครลงทัวร์นาเมนต์ระดับไหนได้**

สองอย่างนี้รวมกันคือช่องโหว่ และเป็นช่องโหว่ **แบบเดียวกับที่ตั๋ว LSN-0024
ตัดสินไปแล้วว่าจะไม่เปิด**

> ตั๋วนั้นตัดสินว่ารายการเก็บเงินเพิ่ม **ห้ามหักเครดิต** เพราะผู้จัดพิมพ์ชื่อและ
> จำนวนเงินเอง ถ้าหักได้จะกลายเป็นช่องให้สร้างรายการปลอมลงชื่อคนที่ไม่ถูกกัน
> แล้วทำคะแนนเขาร่วง

การให้คะแนนฝีมือแย่กว่านั้นอีก เพราะมัน **เป็นความเห็นโดยธรรมชาติ** ไม่มีทางพิสูจน์ว่า
ใครให้คะแนนไม่ตรง และเมื่อคะแนนเป็นตัวกำหนดว่าลงระดับไหนได้ มันก็มีมูลค่าให้โกง

**สองรูปแบบการโกงที่เกิดแน่ถ้าไม่กัน:**

1. **กดคะแนนตัวเองและพวกให้ต่ำ** เพื่อลงรุ่นที่อ่อนกว่าแล้วกวาดรางวัล —
   นี่คือปัญหาคลาสสิกของทุกระบบจัดอันดับที่ให้คนบอกฝีมือตัวเอง
2. **ดันคะแนนคู่แข่งให้สูง** เพื่อผลักเขาไปรุ่นที่เขาสู้ไม่ไหว

### เสนอ: คะแนนที่กำหนดรุ่นต้องมาจาก **ผลการแข่ง** ไม่ใช่ความเห็น

ทัวร์นาเมนต์ผลิตข้อมูลที่โกงยากอยู่แล้ว คือ **ใครชนะใคร** การจะทำให้คะแนนตัวเองต่ำ
แปลว่าต้องแพ้จริง ซึ่งมีราคาที่ต้องจ่าย ต่างจากการกดตัวเลขในฟอร์ม

| แกน | มาจากไหน | ใช้ทำอะไร |
| --- | --- | --- |
| **ฝีมือ** | ผลแมตช์ที่บันทึกในระบบ | **กำหนดรุ่นที่ลงได้** |
| ความประทับใจ | เพื่อนร่วมสนามให้ | แสดงบนโปรไฟล์ · **ไม่กำหนดรุ่น** |

การประเมินกันเองยังมีอยู่ตาม flow ที่ต้องการ แต่ถูกย้ายไปอยู่แกนที่ไม่มีมูลค่าให้โกง
เช่น มาตรงเวลา · มารยาท · เล่นด้วยแล้วสนุก

**ข้อยกเว้นเดียว:** คนใหม่ที่ยังไม่เคยแข่งต้องมีคะแนนตั้งต้น ให้ใช้การประเมินของเพื่อน
ร่วมก๊วนเป็นจุดเริ่ม **พร้อมป้ายว่ายังไม่ยืนยัน** แล้วให้ผลแมตช์เป็นตัวปรับ
ผู้จัดทัวร์เห็นได้ว่าคะแนนไหนยังไม่ผ่านสนามจริง

### อย่าคิดมาตรวัดขึ้นมาเอง — วงการแบดไทยมีอยู่แล้ว

คนเล่นแบดในไทยใช้ระบบ **"มือ"** กันอยู่แล้ว (มือใหม่ · N · S · P · C · B · A)
และประกาศรับสมัครก๊วนก็เขียนกันแบบนี้อยู่แล้ว เช่น "รับมือ N–S"

การสร้างสเกลใหม่แปลว่าต้องสอนคนทั้งตลาด ส่วนการใช้ของเดิมแปลว่าเข้าใจทันที —
หลักการเดียวกับที่โปรดักต์นี้เลือกใช้คำว่า "ก๊วน" และเลือกอยู่บน LINE แทนที่จะทำแอป

**ข้อควรระวัง:** ลำดับมือมีรายละเอียดต่างกันบ้างตามสนามและรายการ spec นี้จึงเสนอให้
**เลือกหนึ่งลำดับแล้วประกาศให้ชัด** ว่าแพลตฟอร์มนี้ใช้แบบไหน ไม่ใช่พยายามรองรับทุกแบบ

## คะแนนสองตัวที่ห้ามปนกัน

หลังฟีเจอร์นี้ คนหนึ่งคนจะมีตัวเลขสองตัว และมันคนละเรื่องกันสิ้นเชิง

| | `player_credit.score` (LSN-0019) | คะแนนฝีมือ (ใหม่) |
| --- | --- | --- |
| วัดอะไร | จ่ายเงินตรงไหม มาตามนัดไหม | ตีเก่งแค่ไหน |
| ใช้ตัดสินอะไร | ได้สิทธิ์จ่ายทีหลังไหม | ลงรุ่นไหนได้ |
| ใครทำให้ขยับ | ระบบ จากเหตุการณ์ที่ตรวจสอบได้ | ผลแมตช์ |

**ห้ามรวมเป็นตัวเลขเดียว และห้ามให้ตัวหนึ่งไปขยับอีกตัว** มือเก่งที่เบี้ยวเงินยังควร
ถูกตัดสิทธิ์จ่ายทีหลัง และมือใหม่ที่จ่ายตรงเวลาไม่ควรได้ลงรุ่นที่เกินตัว

## Design — ของใหม่ที่ต้องมี

```
groups                     ก๊วนที่คงอยู่ข้ามครั้ง
  id · name · sport_id · home_district · created_by · created_at

group_members              ใครอยู่ก๊วนไหน
  group_id · user_id · role(owner|member) · joined_at

tournaments                งานแข่ง
  id · host_group_id · title · starts_at · ends_at
  min_teams · max_teams     ขั้นต่ำคือประตูบานที่หนึ่ง
  entry_fee_thb             ค่าสมัครต่อก๊วน
  tier                      รุ่นที่เปิดรับ (ระบบมือ)
  status                    ใช้รูปเดียวกับ sessions: draft → open → ready → booked → completed
  registration_deadline     ครบไม่ทันภายในเวลานี้ = คืนเงินเต็ม

tournament_teams           ก๊วนที่ลงสมัคร
  tournament_id · group_id · payment_id · joined_at

matches                    ผลการแข่ง — เป็นแหล่งเดียวของคะแนนฝีมือ
  id · tournament_id · court_id · played_at
  side_a_participants · side_b_participants · score_a · score_b
  recorded_by · confirmed_by      ต้องมีคนจากอีกฝั่งยืนยัน

player_skill               คะแนนฝีมือ แยกจาก player_credit เด็ดขาด
  user_id · tier · rating · provisional · matches_played · updated_at
```

**หมายเหตุเรื่อง `matches.confirmed_by`:** ผลแมตช์ที่ฝั่งเดียวกรอกได้เองคือช่องโหว่
เดียวกับการให้คะแนนกันเอง ต้องให้อีกฝั่งยืนยันก่อนจึงนับเข้าคะแนน

**คะแนนเฉลี่ยของก๊วนไม่ต้องเก็บเป็นคอลัมน์** คำนวณจากสมาชิกได้ และการเก็บไว้
จะทำให้มันเพี้ยนทันทีที่มีคนเข้าออกก๊วน — บทเรียนเดียวกับที่ LSN-0024 ตัดสินว่า
ส่วนแบ่งค่าใช้จ่ายต้องเก็บเป็นแถว ไม่คำนวณสด แต่กลับด้านกัน เพราะอันนั้นคือ*หนี้*
ที่ต้องนิ่ง ส่วนอันนี้คือ*ภาพปัจจุบัน*ที่ต้องสด

## Non-goals

- ไม่ทำระบบสายการแข่ง (bracket) อัตโนมัติในรอบแรก — วันงานทวนกติกากันเองตาม flow
- ไม่ทำการถ่ายทอดสด ไม่ทำสถิติรายแต้ม
- ไม่ทำเงินรางวัลผ่านระบบ — เป็นเรื่องกฎหมายคนละเรื่อง
- ไม่รองรับกีฬาอื่น (โปรดักต์แคบลงเหลือแบดมินตันแล้ว)
- ไม่ให้คะแนนฝีมือไปยุ่งกับ `player_credit` ไม่ว่าทางใด

## Decisions — ตัดสินครบแล้ว 12 ก.ย. 2569

### 1. ก๊วนถาวรเป็นตั๋วแยกและมาก่อน → **ใช่**

ทุกอย่างใน flow พึ่งมัน และมันมีประโยชน์ของตัวเองตั้งแต่วันแรกแม้ยังไม่มีทัวร์นาเมนต์
คือตั้งนัดซ้ำโดยไม่ต้องชวนคนใหม่ทุกครั้ง → **LSN-0026**

**ข้อสำคัญที่ตัดสินพ่วงมา: ก๊วนต้องเป็นของ *ไม่บังคับ*** นัดหนึ่งนัดผูกกับก๊วนก็ได้
ไม่ผูกก็ได้ ถ้าบังคับให้ต้องมีก๊วนก่อนถึงตั้งนัดได้ จะพังคุณสมบัติที่เป็นหัวใจของ
โปรดักต์ — ลิงก์เดียวที่ใครก็กดเข้ามาได้โดยไม่ต้องสมัครอะไรก่อน

### 2. คำศัพท์ → **ก๊วน = กลุ่มคน · นัด = การเล่นครั้งหนึ่ง · ทีม = ชุดที่ลงแข่ง**

และ **การเปลี่ยนคำต้องมาก่อน LSN-0026 ไม่ใช่ตามหลัง**

วัดต้นทุนจริงแล้ว: คำว่า "ก๊วน" อยู่ใน **40 ไฟล์** — `src/i18n/th.ts` 27 ครั้ง และ
กระจายอยู่ในอีก 39 ไฟล์ประมาณ 100 ครั้ง **ข้อความไทยในโปรเจกต์นี้ไม่ได้รวมศูนย์
ที่ i18n** งานนี้จึงใหญ่กว่าที่คิดตอนเขียน spec ครั้งแรก

แต่เหตุผลที่ยังต้องทำ และต้องทำ **ก่อน**:

- เมนูใน nav ชื่อ **"ก๊วนของฉัน"** ซึ่งวันนี้แปลว่า *นัดของฉัน* ทันทีที่ LSN-0026
  เพิ่มก๊วนที่เป็นกลุ่มคนเข้ามา เมนูนี้จะมีสองความหมายบนหน้าจอเดียวกัน
- ถ้าเปลี่ยนคำ **ก่อน** ที่ก๊วนจะมีตัวตน คำว่า "ก๊วน" จะว่างพอดีให้ของใหม่ใช้
  และไม่มีช่วงที่ผู้ใช้เห็นสองความหมายเลยแม้แต่วันเดียว
- ต้นทุนมีแต่จะสูงขึ้นทุกหน้าจอที่เพิ่มเข้ามา

→ **LSN-0027 ต้อง merge ก่อน LSN-0026 เริ่ม** เลขตั๋วไม่ใช่ลำดับงาน

ภาษาไทยใช้คำว่า "ก๊วน" ได้ทั้งสองความหมายอยู่แล้วโดยธรรมชาติ การเลือกให้
ก๊วน = กลุ่มคน เป็นการเลือกความหมายที่ตรงกับที่คนแบดใช้เวลาพูดถึงชุมชนของตัวเอง
("อยู่ก๊วนนี้มาสองปีแล้ว") ส่วน "นัด" ก็เป็นคำที่ใช้กันอยู่แล้ว ("นัดตีแบดวันพุธ")

### 3. ลงทัวร์นาเมนต์ → **สมัครเป็นก๊วน แต่ล็อกรายชื่อผู้เล่นก่อนวันแข่ง**

ก๊วนคือหน่วยที่จ่ายเงินและเป็นเจ้าของชื่อเสียง ส่วนใครว่างไม่ว่างเป็นรายละเอียด
หน้างานที่เปลี่ยนได้จนถึงกำหนด

**ผลที่ตามมาและเป็นข้อที่พลาดง่ายที่สุด:** การตรวจว่าลงรุ่นไหนได้ ต้องตรวจกับ
**รายชื่อที่ลงเล่นจริง ไม่ใช่ค่าเฉลี่ยของทั้งก๊วน** ก๊วนที่มีสมาชิก 12 คนแล้วส่งมือดี
ที่สุด 4 คนลงรุ่นอ่อน คือการโกงแบบเดียวกับที่ข้อ "คะแนนฝีมือ" พยายามกัน
ค่าเฉลี่ยของทั้งก๊วนจึงเป็นตัวเลขสำหรับ *ดู* ไม่ใช่ตัวเลขสำหรับ *ตัดสิน*

### 4. ค่าสมัคร → **ผู้จัดก๊วนจ่ายก้อนเดียว แล้วไปหารกันเองในก๊วน**

ไม่ต้องสร้างอะไรใหม่เลย ค่าสมัครกลายเป็นค่าใช้จ่ายก้อนหนึ่งที่กลไกเก็บเงินของก๊วน
จัดการอยู่แล้ว และทำให้บัญชีฝั่งทัวร์นาเมนต์ง่ายที่สุดเท่าที่เป็นไปได้ คือ
**หนึ่งทีม หนึ่งการจ่าย**

ประตู "เงินครบ" ของทัวร์นาเมนต์จึงนับ *การจ่ายระดับทีม* ไม่ใช่รายคน

### 5. ลำดับมือ → **N · S · P · C · B · A** หกระดับ เรียงจากใหม่ไปเก่ง

เก็บเป็น enum ที่มีลำดับ เพื่อให้เทียบมากกว่า/น้อยกว่าได้

**สิ่งที่ต้องระวังและเขียนไว้ให้ชัด:** ลำดับมือในวงการแบดไทยมีรายละเอียดต่างกัน
ตามสนามและรายการ บางที่แยก P เป็น P- / P / P+ บางที่มีมือหน้าบ้าน
แพลตฟอร์มนี้จึง **เลือกหนึ่งลำดับแล้วประกาศว่าใช้แบบนี้** ไม่พยายามรองรับทุกแบบ
และไม่อ้างว่าเป็นมาตรฐานกลางของวงการ

ตอนเริ่มให้ **ผู้เล่นประกาศมือของตัวเอง** พร้อมป้ายว่ายังไม่ยืนยัน แล้วให้ผลแมตช์
เป็นตัวปรับ — ประกาศเองไม่ใช่ปัญหาตราบใดที่มันถูกผลจริงแก้ได้

## Acceptance criteria (ระดับ spec)

- [ ] ก๊วนคงอยู่ข้ามการนัดเล่น และมีสมาชิก
- [ ] ผู้จัดสร้างทัวร์นาเมนต์พร้อมวัน เวลา คอร์ต ค่าสมัคร และขั้นต่ำจำนวนทีมได้
- [ ] ก๊วนอื่นสมัครผ่านลิงก์เดียวที่แชร์เข้า LINE ได้
- [ ] ทีมไม่ถึงขั้นต่ำภายในกำหนด → **คืนเงินเต็มทุกก๊วน** — ปักด้วยเทส
- [ ] ผลแมตช์ต้องมีอีกฝั่งยืนยันก่อนจึงนับเข้าคะแนน — ปักด้วยเทส
- [ ] คะแนนฝีมือขยับได้จากผลแมตช์เท่านั้น **ไม่ขยับจากการประเมินของเพื่อน** — ปักด้วยเทส
- [ ] `player_credit` ไม่ขยับเลยจากอะไรก็ตามในฟีเจอร์นี้ — ปักด้วยเทส
- [ ] คะแนนของคนที่ยังไม่เคยแข่งถูกป้ายว่ายังไม่ยืนยัน
- [ ] คะแนนเฉลี่ยของก๊วนคำนวณสดจากสมาชิก ไม่เก็บเป็นคอลัมน์

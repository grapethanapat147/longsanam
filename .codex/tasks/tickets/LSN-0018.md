# LSN-0018 — Session lifecycle completion

**Type:** Feature · **Phase:** 7 · **Status:** Done

## Goal
Sessions currently never leave `booked`, and a session whose time passed
without a court strands the players' money.

## Acceptance criteria
- [x] `complete_finished_sessions()` moves `booked` sessions past `ends_at`
      to `completed`, with an audit row.
- [x] Sessions past `starts_at` that never secured a court are cancelled and
      every paid participant is refunded in full, per the stated policy that
      players are made whole when the platform could not deliver a court.
- [x] Both sweeps run from `/api/cron/expire` and the admin maintenance button.
- [x] The refund-all loop is shared with `cancelSessionAction` rather than
      duplicated.

## Review notes
- A stranded session is reported to `calculateRefund` as `booking_failed`
  rather than its stored status. That matters: the time-based tiers would
  otherwise return 0% (the start time has passed by definition), so an
  organizer who had turned off `organizerCancelAlwaysFullRefund` would leave
  players out of pocket for a platform failure.
- The refund fan-out was extracted to `src/lib/refunds.ts`, deliberately not a
  `'use server'` module — every export of such a file becomes a callable server
  action, and this one refunds an entire session.
- Verified: a finished session became `completed`, a stranded session was
  cancelled with all 3 players refunded in full, and running the sweep three
  times left exactly 3 refunds totalling 300 THB.

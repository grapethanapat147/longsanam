# 🟢 LSN-0036 — หาทัวร์นาเมนต์ที่เปิดรับสมัครได้ โดยไม่ต้องมีลิงก์

**Type:** Feature · **Phase:** 10 · **Status:** Done
**Source:** ของค้างที่บันทึกไว้ใน Done Notes ของ LSN-0032 และ LSN-0034
**Depends on:** LSN-0029 · LSN-0032 · LSN-0034 — merge แล้วทั้งหมด

## Goal

ให้คนที่ยังไม่ได้รับลิงก์ **หาทัวร์นาเมนต์ที่เปิดรับสมัครเจอ** จากหน้า `/discover`

## Context

หลัง LSN-0034 หน้าแรกชวนคนมา *จัด* ทัวร์นาเมนต์แล้ว แต่คนที่อยาก *หา* งานเข้าร่วม
ยังไม่มีที่ให้ดูเลย ทัวร์นาเมนต์มองเห็นได้ทางเดียวคือมีคนส่งลิงก์ `/t/<code>` ให้

**นี่คือรูโหว่กลางเส้นทางหลักของสินค้า** — เอกสารแนวคิดวัดความสำเร็จด้วย
"ก๊วนที่ไม่เคยเจอกันมาก่อน ได้ลงแข่งด้วยกันจริงกี่ครั้ง" ซึ่งเกิดไม่ได้ถ้าก๊วนสองก๊วน
ต้องรู้จักกันอยู่ก่อนถึงจะส่งลิงก์หากันได้

### ทำไมต้องมี RPC ใหม่ ใช้ RLS เดิมไม่ได้

policy ปัจจุบันปิดสนิทสำหรับคนนอก

```sql
create policy tournaments_read on public.tournaments
  for select to authenticated
  using (is_tournament_host(id) or is_tournament_team_member(id) or is_platform_admin());
```

`anon` ไม่มีสิทธิ์อะไรเลย และ `authenticated` ที่ไม่ได้อยู่ในงานก็อ่านไม่ได้
การผ่อน policy ให้คนนอกอ่านตารางตรง ๆ จะเปิดทุกคอลัมน์ รวมถึงของที่ไม่ควรเปิด
— **RLS เป็น row-level ไม่ใช่ column-level** (บทเรียน LSN-0023) การปกปิดฟิลด์
ต้องแปลว่า "ไม่คืนฟิลด์นั้น" ไม่ใช่ "คืนแล้วซ่อนบนหน้าจอ"

จึงใช้แพตเทิร์นเดียวกับ `tournament_invite_public(text)` ที่มีอยู่แล้ว คือ
`security definer` ที่ประกอบ JSON เฉพาะฟิลด์ที่ตั้งใจเปิด

## Scope

- RPC ใหม่ `public_open_tournaments()` — คืนรายการงานที่เปิดรับสมัครอยู่จริง
- หน้า `/discover` แยกเป็นสองแท็บด้วย query param: **นัด** (ค่าเริ่มต้น) กับ **ทัวร์นาเมนต์**
- การ์ดทัวร์นาเมนต์ลิงก์ไป `/t/<code>` ซึ่งเป็นหน้าสมัครที่มีอยู่แล้ว

## Non-goals

- ไม่ทำค้นหา ไม่ทำตัวกรองรุ่น/เขต — ยังไม่มีงานมากพอที่จะต้องกรอง
- ไม่แตะ `tournament_invite_public` ที่มีอยู่
- ไม่แตะ policy `tournaments_read` — งานนี้เพิ่มทางอ่านใหม่ ไม่ผ่อนทางเดิม
- ไม่เปลี่ยนชื่อเมนู `หานัด` — ป้ายเมนูเป็นชื่อของ "หน้าหา" ไม่ใช่ชื่อแท็บ

## Decisions

### แท็บบน `/discover` ไม่ใช่หน้าใหม่

`/discover` คือประตู "หา" ที่มีอยู่แล้วและมีเมนูชี้มาแล้ว การเพิ่มหน้าที่สอง
แปลว่าต้องเพิ่มเมนูที่สองที่แข่งกันเอง ส่วนแท็บใช้ query param แบบเดียวกับตัวกรอง
`?sport=` ที่หน้านี้ใช้อยู่ จึง server-render ได้ทั้งหมด ไม่ต้องมี state ฝั่ง client

### ค่าเริ่มต้นคือแท็บ "นัด"

ป้ายเมนูเขียนว่า "หานัด" ถ้าเปิดมาแล้วเจอทัวร์นาเมนต์ก่อน ป้ายกับของที่เห็นจะไม่ตรงกัน
คนที่อยากหาทัวร์นาเมนต์กดแท็บเพิ่มหนึ่งครั้ง ซึ่งถูกกว่าการทำให้ป้ายโกหก

### กรองเวลาปิดรับสมัครใน SQL ไม่ใช่บนหน้าจอ

งานที่เลยกำหนดแล้วแต่ยังไม่ถูกกวาดโดย `close_unfilled_tournaments()` จะยังเป็น
`open` อยู่ชั่วคราว ถ้ากรองบนหน้าจอ คนจะเห็นงานที่สมัครไม่ได้แล้ว แล้วกดเข้าไปเจอทางตัน

# 🔴 LSN-0035 — คืนเงินอัตโนมัติเมื่อทีมไม่ครบ ยังไม่มีใครสั่งให้ทำงาน

**Type:** Bugfix · **Phase:** 10 · **Status:** Done
**Source:** พบตอนสรุปของค้างหลัง LSN-0032

## Goal

ทำให้คำสัญญาที่แสดงบนหน้าจอว่า **"ถ้าทีมไม่ครบภายใน … ทุกก๊วนได้เงินคืนเต็ม"**
เกิดขึ้นจริงโดยไม่ต้องมีคนไปกด

## อาการ

หน้าทัวร์นาเมนต์แสดงข้อความนี้กับผู้ใช้ทุกคน (`t.tournaments.deadlineHint`)

> ถ้าทีมไม่ครบภายใน {วันที่} ทุกก๊วนได้เงินคืนเต็ม

แต่ `close_unfilled_tournaments()` ซึ่งเป็นตัวที่ทำสิ่งนี้ **ไม่มีอะไรเรียกมันเลย**
ทัวร์นาเมนต์ที่เลยกำหนดปิดรับสมัครโดยทีมไม่ครบจะค้างสถานะ `open` ตลอดไป
และเงินค่าสมัครที่จ่ายมาแล้วจะไม่ถูกคืน

**นี่คือเงินของผู้ใช้ที่ค้างอยู่ในระบบโดยที่เราบอกเขาไปแล้วว่าจะคืนให้**

## ต้นตอ

`runLifecycleSweeps()` ใน `src/lib/lifecycle.ts:39` เรียก RPC ตามเวลาอยู่ห้าตัว

```
expire_stale_holds · expire_overdue_payments · expire_waitlist_promotions
complete_finished_sessions · mark_no_shows
```

LSN-0029 เขียน `close_unfilled_tournaments()` ขึ้นมาพร้อม `grant execute … to service_role`
แต่ **ไม่ได้เติมเข้าไปในรายการนี้** ฟังก์ชันจึงสมบูรณ์ดีและมีเทส pgTAP ของตัวเอง
แต่ไม่มีวันถูกเรียกในชีวิตจริง

### รูปแบบบั๊กที่ต้องกันไม่ให้เกิดซ้ำ

ระบบมี RPC ที่ `grant` ให้ **`service_role` อย่างเดียว** อยู่สี่ตัว ซึ่งแปลว่า
"ฟังก์ชันของเครื่อง ต้องมีโค้ดเป็นคนเรียก เพราะผู้ใช้เรียกเองไม่ได้"

| ฟังก์ชัน | มีคนเรียกไหม |
| --- | --- |
| `list_chaseable_participants` | มี |
| `record_chase` | มี |
| `mark_no_shows` | มี |
| **`close_unfilled_tournaments`** | **ไม่มี** |

ไม่มีอะไรในระบบที่จับได้ว่าตัวที่สี่หลุด — เทส pgTAP เขียวเพราะมันเรียกฟังก์ชันตรง ๆ
ส่วนเทส TypeScript ไม่เคยแตะชั้นนี้เลย

## Scope

- เติม `close_unfilled_tournaments` เข้า `runLifecycleSweeps()` และ `SweepResult`
- **เทสดักรูปแบบ** ที่อ่าน migration หา RPC ซึ่ง grant ให้ `service_role` อย่างเดียว
  แล้วยืนยันว่าทุกตัวถูกอ้างถึงใน `src/` — ดักทั้งคลาสของบั๊ก ไม่ใช่ดักเคสนี้เคสเดียว

## Non-goals

- ไม่แก้ตัวฟังก์ชัน `close_unfilled_tournaments()` — มันถูกต้องอยู่แล้วและมีเทสของตัวเอง
- ไม่ตั้ง cron job ใหม่ — ตัวจับเวลาที่ cron-job.org ยิง `/api/cron/expire` อยู่แล้ว
  การเติมเข้า sweep เดิมจึงได้ตัวจับเวลาฟรี
- ไม่แตะ RPC ตัวอื่นใน sweep

## Decisions

### เติมเข้า sweep เดิม ไม่สร้าง endpoint ใหม่

`/api/cron/expire` มีตัวจับเวลาจริงยิงอยู่แล้วที่ cron-job.org และมีด่านตรวจ
`CRON_SECRET` อยู่แล้ว การสร้าง endpoint ที่สองแปลว่าต้องไปตั้ง job ใหม่ ต้องจัดการ
secret อีกชุด และเพิ่มที่ให้ลืมอีกหนึ่งที่ — ซึ่งเป็นความผิดพลาดแบบเดียวกับที่ตั๋วนี้กำลังแก้

### เทสดักรูปแบบ ไม่ใช่เทสดักชื่อฟังก์ชันตัวเดียว

เขียนเทสว่า `lifecycle.ts` ต้องมีคำว่า `close_unfilled_tournaments` ก็แก้บั๊กนี้ได้
แต่ไม่กันตัวที่ห้าที่จะถูกลืมในอนาคต เทสจึงอ่านสิทธิ์จาก migration เป็นแหล่งความจริง
แล้วบังคับว่า **ทุก** ฟังก์ชันของเครื่องต้องมีคนเรียก

## Blocking notes

- ไม่ทับกับตั๋วอื่น — แตะ `src/lib/lifecycle.ts` กับไฟล์เทสใหม่เท่านั้น
- ไม่ต้องมี migration ใหม่ จึงมีผลบน production ทันทีที่ deploy

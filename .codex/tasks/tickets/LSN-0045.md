# 🔴 LSN-0045 — ยืนยันผลแมตช์ใช้ไม่ได้เลย + ประตูจ่ายเงินตอบไม่เหมือนกันตามคนดู

**Type:** Bugfix · **Phase:** 10 · **Status:** Done
**Source:** เดิน flow สมัครเข้าแข่ง → จ่าย → ยืนยันคอร์ต → บันทึกผล บนเบราว์เซอร์จริง

## บั๊ก 1 — กด "ยืนยันผล" แล้วขึ้น "เกิดข้อผิดพลาดที่ไม่คาดคิด" ทุกครั้ง

```
code:    21000
message: DELETE requires a WHERE clause
```

บทบาท `authenticator` ที่ PostgREST ใช้ต่อฐานข้อมูลถูกตั้งไว้ว่า

```
session_preload_libraries = supautils, safeupdate
```

ส่วนขยาย `safeupdate` ปฏิเสธ DELETE/UPDATE ที่ไม่มี WHERE **ทุกคำสั่งในคำขอนั้น**
รวมถึงคำสั่งที่อยู่ข้างในฟังก์ชัน `security definer` ด้วย เพราะเป็นการตั้งค่าระดับ
session ไม่ใช่ระดับสิทธิ์

`recompute_player_skill()` (LSN-0031) ล้างตารางด้วย `delete from public.player_skill;`
แล้วปิดท้ายด้วย `update ... set tier = ...` ที่ไม่มี WHERE ทั้งคู่จึงถูกปฏิเสธ
`confirm_match` และ `void_match` ที่เรียกต่อจึงล้มทั้งคำสั่ง

**ขอบเขตความเสียหาย:** บั๊กนี้อยู่บน production ด้วย แปลว่า
**ยังไม่เคยมีใครยืนยันผลแมตช์ผ่านหน้าเว็บได้สำเร็จเลย** แมตช์ที่เห็นในระบบมาจาก
seed ทั้งหมด ซึ่งรันในสิทธิ์ `postgres`

### ทำไม pgTAP ถึงเขียวมาตลอด

`safeupdate` preload ที่บทบาท `authenticator` เท่านั้น เทสรันในสิทธิ์ `postgres`
จึงไม่โดน — **จุดบอดเดียวกับ LSN-0043 เป๊ะ** คือเทสเดินคนละทางกับผู้ใช้จริง

## บั๊ก 2 — ประตู "ทุกทีมจ่ายแล้ว" ตอบไม่เหมือนกันตามคนดู

ข้อมูลชุดเดียวกัน หน้าเดียวกัน คนละคำตอบ

| คนดู | เห็น |
| --- | --- |
| เจ้าภาพ | `2/2 ครบแล้ว` · ทั้งสองก๊วน "จ่ายแล้ว" |
| ก๊วนที่สมัครเข้ามา | `1/2 ยังไม่ครบ` · เจ้าภาพขึ้น "ยังไม่จ่าย" ทั้งที่จ่ายแล้ว |

policy ของ `tournament_team_payments` เปิดให้อ่านเฉพาะ

```
is_tournament_host(tournament_id) OR is_group_member(group_id) OR is_platform_admin()
```

ก๊วนที่ไม่ใช่เจ้าภาพจึงเห็นแค่แถวของตัวเอง หน้ารายละเอียดที่นับจากชุดนั้นเลยผิด

อาการนี้เคยถูกบันทึกไว้ตอน LSN-0029 ว่า "ทุกทีมจ่ายแล้ว 1/2" แต่ไม่ได้เปิดตั๋ว

## Scope

- `recompute_player_skill()` ใส่ WHERE ให้ DELETE และ UPDATE (migration ใหม่ +
  แก้ไฟล์เดิมด้วย เพื่อให้ `db reset` ได้ของที่ถูกตั้งแต่แรก)
- `tournament_paid_groups(uuid)` — RPC `security definer` คืนเฉพาะ `group_id`
  ของทีมที่จ่ายแล้ว
- หน้ารายละเอียดทัวร์นาเมนต์เรียก RPC แทนอ่านตารางตรง + log error
- `src/types/database.ts` เติม RPC ใหม่ (ไฟล์นี้เขียนมือ)

## Decisions

### ไม่ขยาย policy ของ `tournament_team_payments`

RLS เป็น row-level ไม่ใช่ column-level การเปิดแถวให้อ่านคือการเปิด `amount_thb` ·
`paid_by` · `provider_ref` · `idempotency_key` ไปด้วยทั้งชุด ซึ่งไม่เกี่ยวกับสิ่งที่
หน้าจอต้องรู้เลย — บทเรียนเดียวกับ LSN-0023 และ LSN-0036 คือ "ปิดข้อมูล" ต้องแปลว่า
**ไม่คืนฟิลด์นั้น**

### `where user_id is not null` ไม่ใช่โค้ดขยะ

`user_id` เป็น primary key เงื่อนไขนี้จึงไม่กรองอะไรออก แต่เป็นสิ่งเดียวที่ทำให้
`safeupdate` ยอมให้คำสั่งผ่าน มีคอมเมนต์กำกับไว้ทั้งสองจุด

### ตัวเฝ้าเป็น vitest ที่อ่านไฟล์ migration ไม่ใช่ pgTAP

pgTAP รันในสิทธิ์ `postgres` จึงพิสูจน์เรื่องนี้ไม่ได้เลยไม่ว่าจะเขียนยังไง
ตัวเฝ้าจึงต้องอ่านไฟล์ตรง ๆ เหมือน `machine-rpc-has-caller.test.ts`

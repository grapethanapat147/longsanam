# LSN-0002 — Database schema and migrations

**Type:** Feature · **Phase:** 1 · **Status:** Done

## Goal
Model the full domain in Postgres with constraints that make double booking impossible.

## Acceptance criteria
- [x] Enums for session, participant, booking, payment, refund, hold states.
- [x] Tables: profiles, sports, venues, venue_members, courts, court_sports,
      court_availability, court_price_rules, sessions, session_venue_preferences,
      session_participants, waitlist_entries, court_holds, bookings, payments,
      refunds, notifications, audit_logs.
- [x] `btree_gist` exclusion constraint prevents overlapping active holds per court.
- [x] `btree_gist` exclusion constraint prevents overlapping live bookings per court.
- [x] `audit_logs` is append-only (UPDATE/DELETE blocked by trigger).
- [x] Atomic RPCs: `try_hold_court`, `confirm_booking`, `release_hold`,
      `expire_stale_holds`, `promote_waitlist`.
- [x] Every RPC is idempotent via an idempotency key.

## Notes
Race conditions are handled with `pg_advisory_xact_lock` keyed on court id, so
concurrent booking attempts on the same court serialize instead of colliding.

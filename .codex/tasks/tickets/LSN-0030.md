# 🟢 LSN-0030 — บันทึกผลแมตช์ + ยืนยันสองฝั่ง

**Type:** Feature · **Phase:** 10 · **Status:** Backlog
**Spec:** `.codex/specs/tournaments.md` หัวข้อ "เรื่องที่อันตรายที่สุด: คะแนนฝีมือ"
**Depends on:** LSN-0029 — **merge เข้า main แล้ว 17 ก.ย. 2569**

## Goal

บันทึกผลการแข่งรายแมตช์ในทัวร์นาเมนต์ และ **ผลจะนับได้ก็ต่อเมื่ออีกฝั่งยืนยัน**

ตั๋วนี้ไม่ได้คิดคะแนนอะไรทั้งนั้น มันสร้าง **แหล่งข้อมูลที่โกงยาก** ให้ LSN-0031
ใช้คิดคะแนนฝีมือทีหลัง

## Context

`.codex/specs/tournaments.md` ตัดสินไว้ว่าคะแนนที่กำหนดรุ่นต้องมาจาก
**ผลการแข่ง ไม่ใช่ความเห็น** เหตุผลคือทัวร์นาเมนต์ผลิตข้อมูลที่โกงยากอยู่แล้ว
คือ *ใครชนะใคร* — การทำให้คะแนนตัวเองต่ำแปลว่าต้องแพ้จริง ซึ่งมีราคาที่ต้องจ่าย
ต่างจากการกดตัวเลขในฟอร์ม

**แต่ข้อมูลนั้นจะโกงยากก็ต่อเมื่อฝั่งเดียวกรอกเองไม่ได้** สเปกเขียนไว้ตรง ๆ ว่า

> ผลแมตช์ที่ฝั่งเดียวกรอกได้เองคือช่องโหว่เดียวกับการให้คะแนนกันเอง
> ต้องให้อีกฝั่งยืนยันก่อนจึงนับเข้าคะแนน

**การยืนยันสองฝั่งจึงเป็นหัวใจของตั๋วนี้ ไม่ใช่ของแถม** ถ้าข้อนี้พัง
คะแนนฝีมือทั้งระบบใน LSN-0031 ก็ไร้ความหมายตั้งแต่วันแรก

ของที่พึ่งมีครบแล้ว — `tournaments`, `tournament_teams`, `groups`,
`group_members` และกลไก `app_log()`

## Scope

- ตาราง `matches` พร้อมรายชื่อผู้เล่นสองฝั่งและสกอร์
- บันทึกผล · ยืนยันโดยอีกฝั่ง · โต้แย้งผล
- สถานะแมตช์: `recorded → confirmed` และ `recorded → disputed`
- หน้าจอบันทึกผลและยืนยันผล ฝั่งเจ้าภาพและฝั่งทีม
- นับเฉพาะแมตช์ที่ `confirmed` เท่านั้นในทุกที่ที่อ่านผล

## Non-goals

- **ไม่คิดคะแนนฝีมือ ไม่มีตาราง `player_skill`** — LSN-0031
- ไม่ทำ bracket หรือจัดตารางแข่งอัตโนมัติ — spec ระบุเป็น non-goal
- ไม่ทำสถิติรายแต้ม ไม่ถ่ายทอดสด
- ไม่ตัดสินอันดับสุดท้ายของทัวร์นาเมนต์ (แชมป์) — ดู Open Questions ข้อ 3
- ไม่แตะ `player_credit` และไม่แตะ `payments` ไม่ว่าทางใด

## Decisions — มาจาก spec แล้ว ผูกพันตั๋วนี้

### 1. ผลนับได้ต่อเมื่ออีกฝั่งยืนยัน

แมตช์ที่เพิ่งบันทึกอยู่สถานะ `recorded` ซึ่ง **ยังไม่นับเป็นผลการแข่ง**
ต้องมีคนจากทีมตรงข้ามกดยืนยันจึงกลายเป็น `confirmed`

### 2. คนที่บันทึกยืนยันเองไม่ได้ และคนในทีมเดียวกันก็ยืนยันแทนไม่ได้

ถ้าคนในทีมเดียวกันยืนยันได้ การยืนยันก็ไม่ได้แปลว่าอะไรเลย
ต้องเป็นสมาชิกของ **ก๊วนฝั่งตรงข้ามในแมตช์นั้น**

### 3. โต้แย้งได้ และผลที่ถูกโต้แย้งไม่นับ

สเปกเขียนว่า *"กรณีขัดแย้งให้รอผู้จัดตรวจ ยังไม่ส่งผลต่อคะแนน"*
สถานะ `disputed` จึงมีค่าเท่ากับ `recorded` ในแง่การนับ คือ **ไม่นับ**

### 4. เก็บรายชื่อผู้เล่นสองฝั่ง ไม่ใช่แค่ชื่อก๊วน

Decision 3 ของสเปกบอกว่าการตรวจรุ่นต้องตรวจกับ **รายชื่อที่ลงเล่นจริง
ไม่ใช่ค่าเฉลี่ยของทั้งก๊วน** เพราะก๊วน 12 คนที่ส่งมือดีสุด 4 คนลงรุ่นอ่อน
คือการโกงแบบเดียวกับที่ระบบพยายามกัน

→ `matches` ต้องเก็บ **ว่าใครลงเล่นจริงในแมตช์นั้น** ไม่งั้น LSN-0031
จะไม่มีข้อมูลให้ตรวจ

## Design

```sql
create type public.match_status as enum ('recorded', 'confirmed', 'disputed', 'voided');

create table public.matches (
  id              uuid primary key default gen_random_uuid(),
  tournament_id   uuid not null references public.tournaments(id) on delete cascade,
  side_a_group_id uuid not null references public.groups(id),
  side_b_group_id uuid not null references public.groups(id),
  side_a_players  uuid[] not null,
  side_b_players  uuid[] not null,
  score_a         integer not null check (score_a >= 0),
  score_b         integer not null check (score_b >= 0),
  court_label     text,                      -- ป้ายสำหรับคนอ่าน ไม่มีอะไรคำนวณจากมัน
  played_at       timestamptz not null default now(),
  status          public.match_status not null default 'recorded',
  recorded_by     uuid not null references public.profiles(id),
  confirmed_by    uuid references public.profiles(id),
  confirmed_at    timestamptz,
  disputed_by     uuid references public.profiles(id),
  disputed_at     timestamptz,
  dispute_note    text,
  voided_by       uuid references public.profiles(id),
  voided_at       timestamptz,
  void_reason     text,
  created_at      timestamptz not null default now(),
  check (side_a_group_id <> side_b_group_id),
  check (array_length(side_a_players, 1) between 1 and 2),
  check (array_length(side_b_players, 1) between 1 and 2),
  -- ยืนยันแล้วต้องมีคนยืนยัน และคนยืนยันต้องไม่ใช่คนบันทึก
  check (status <> 'confirmed' or (confirmed_by is not null and confirmed_by <> recorded_by))
);
```

**`check (confirmed_by <> recorded_by)` ที่ระดับตาราง ไม่ใช่แค่ใน RPC**
เพราะกติกาข้อนี้คือทั้งหมดของความน่าเชื่อถือของคะแนนในตั๋วถัดไป
ด่านที่อยู่ในโค้ดอย่างเดียวคือด่านที่หายไปได้ตอนมีคนเขียน RPC ตัวที่สอง

- [ ] **คนที่บันทึกยืนยันเองไม่ได้** — ปักด้วยเทส
- [ ] **คนในก๊วนเดียวกับผู้บันทึกยืนยันแทนไม่ได้** — ปักด้วยเทส

## Open Questions — ตัดสินครบแล้ว 17 ก.ย. 2569

### 1. แก้ผลที่ยืนยันแล้ว → **แก้ไม่ได้ แต่เจ้าภาพ `void` ได้ แล้วบันทึกใหม่**

เพิ่มสถานะ `voided` ผลที่ยืนยันแล้วจะไม่ถูกแก้ตัวเลขในแถวเดิมเด็ดขาด
ถ้าผิดจริง เจ้าภาพกด void พร้อมเหตุผล แล้วบันทึกแมตช์ใหม่ให้ถูก
แล้วให้อีกฝั่งยืนยันใหม่ตามปกติ

**เหตุผลที่ไม่เลือก "แก้ไม่ได้เลย"** ผลที่ผิดและซ่อมไม่ได้จะปนเปื้อนคะแนนฝีมือ
ถาวร ซึ่งแย่กว่าความยุ่งยากของการมีทางออก

**เหตุผลที่ไม่เลือก "แก้ตัวเลขในแถวเดิม"** ถ้าแถวที่ยืนยันแล้วเปลี่ยนค่าได้
LSN-0031 ต้องมีกลไกคิดคะแนนย้อนหลัง ซึ่งเป็นความซับซ้อนคนละระดับ
แต่ถ้าใช้ void แทน **ชุดของแมตช์ที่ `confirmed` แค่เล็กลง** LSN-0031
จึงคิดคะแนนใหม่จากชุดปัจจุบันได้เหมือนเดิม ไม่ต้องรู้ประวัติ

**เฉพาะเจ้าภาพ void ได้ ไม่ใช่ทีมใดทีมหนึ่ง** เพราะทีมที่ void ผลที่ตัวเองแพ้ได้
คือช่องโกงตรงตัว และสเปกวางเจ้าภาพเป็นคนกลางไว้แล้วในเส้นทางข้อโต้แย้ง
(*"กรณีขัดแย้งให้รอผู้จัดตรวจ"*)

**`voided` ไม่นับเหมือน `recorded` และ `disputed`** — มีสถานะเดียวที่นับคือ `confirmed`

### 2. `matches.court_id` → **ตัดทิ้ง ใช้ `court_label text` ที่ไม่บังคับแทน**

LSN-0029 ตัดสินให้เจ้าภาพยืนยันคอร์ตเองด้วย `venue_note` ที่เป็นข้อความ
ระบบจึง **ไม่มีแถวคอร์ตให้ผูก** การใส่ `court_id` ที่ชี้ไป `courts` จะเป็นคอลัมน์
ที่ว่างตลอดไปสำหรับทัวร์นาเมนต์ทุกงานที่ไม่ได้ใช้สนามพันธมิตร ซึ่งคือทุกงานวันนี้

เก็บเป็นข้อความเพราะวันแข่งจริงที่มีหลายคอร์ตวิ่งพร้อมกัน คนเรียกแมตช์กันว่า
"คอร์ต 3" และนั่นคือสิ่งที่ต้องบันทึก **ไม่มีอะไรในระบบอ่านค่านี้ไปคำนวณ**
มันเป็นป้ายสำหรับคนอ่านอย่างเดียว และเขียนไว้ตรงนี้ให้ชัดว่าตั้งใจให้เป็นแบบนั้น

### 3. ใครตัดสินแชมป์ → **เจ้าภาพยืนยันอันดับ แต่ไม่ทำในตั๋วนี้**

**คำตอบของ "ใคร" คือเจ้าภาพ** ซึ่งตรงกับที่ `badge-definitions.json` เขียนไว้แล้ว
ว่า *"ให้หลังผู้จัดยืนยันอันดับสุดท้าย"* ระบบคำนวณเองไม่ได้ เพราะสเปกระบุว่า
**ไม่ทำ bracket และไม่จัดตารางแข่ง** เมื่อไม่มีรูปแบบการแข่งที่ระบบรู้
คำว่า "ใครชนะทั้งรายการ" ก็คำนวณไม่ได้ตามนิยาม

**แต่มันไม่ควรอยู่ในตั๋วนี้** เพราะตั๋วนี้ทั้งใบตั้งอยู่บนหลักว่า
**ไม่มีฝ่ายไหนตัดสินผลได้ฝ่ายเดียว** ส่วนการประกาศแชมป์เป็นการกระทำที่
**เจ้าภาพทำฝ่ายเดียวโดยตั้งใจ** เอาสองอย่างมาไว้ในตั๋วเดียวกันทำให้สารของตั๋วขุ่น
และทำให้คนอ่านโค้ดทีหลังเข้าใจผิดว่าการยืนยันสองฝั่งเป็นทางเลือก

→ **ที่เก็บอันดับสุดท้ายและ RPC ประกาศแชมป์ ย้ายไปอยู่ใน LSN-0028 (Badge)**
ซึ่งเป็นผู้ใช้เพียงรายเดียวของข้อมูลนั้น และเป็นตั๋วที่บล็อกอยู่ด้วยเรื่องนี้พอดี

**ข้อควรระวังที่ต้องยกไปกับมัน:** เจ้าภาพประกาศก๊วนตัวเองเป็นแชมป์ได้
ต้องมีอย่างน้อยหนึ่งแมตช์ที่ `confirmed` ของทีมนั้น และการประกาศต้องเขียน
`audit_logs` และมองเห็นได้จากทุกทีม ไม่ใช่ทำเงียบ ๆ

# 🟢 LSN-0028 — Badge หลังจบทัวร์นาเมนต์

**Type:** Feature · **Phase:** 11 · **Status:** Done
**Spec:** `.codex/specs/badges.md`
**Artwork:** `docs/design/social-tournament/badges/` — เสร็จแล้วทั้งหกใบ
**Depends on:** ~~LSN-0027 → LSN-0026 → ตั๋วทัวร์นาเมนต์~~ — ครบหมดแล้วตั้งแต่ LSN-0029/0030

## Goal

ผู้เล่นได้ badge ที่จับต้องได้หลังลงแข่งจบ เพื่อให้การลงแข่งครั้งนี้มีผลกับครั้งหน้า
และเป็นเหตุผลให้กลับมาลงอีก

## Context

artwork เสร็จแล้วทั้งหกใบ เป็น native vector อยู่ในพาเลตต์ token จริง
พร้อม `badge-definitions.json` ที่เสนอกติกาการให้ไว้แล้ว ตั๋วนี้คือส่วนที่เหลือ
คือฐานข้อมูล กติกา และหน้าจอ

## Scope

- ตาราง `player_badges` พร้อม `unique (user_id, badge_id)`
- ฟังก์ชัน `award_badges(p_user_id, p_tournament_id)` ที่ประเมินทุกใบและ idempotent
- catalog เป็นค่าคงที่ฝั่ง TS อ่านจาก `badge-definitions.json` ไม่มีตาราง catalog
- ตารางสะสมบนหน้าโปรไฟล์ ใบที่ยังไม่ได้แสดงเป็นเงาจาง
- badge ที่เพิ่งได้บนการ์ดหลังจบงาน
- ย้าย `badges/icons/` เข้า `public/` หรือ `src/assets/` ให้แอปเสิร์ฟได้

## Non-goals

- ไม่มี leaderboard เรียงจำนวน badge
- ไม่มี badge ที่ซื้อได้ หรือผู้จัดแจกเองตามใจ
- ไม่ ship `badges/labeled/` เข้าแอป — ใบละ 419KB เพราะฝังฟอนต์ รวม 2.4MB
- ไม่ทำ badge เฉพาะกิจรายอีเวนต์ในรอบแรก

- [ ] `05-fair-play` ไม่ให้เมื่อประเมินตนเอง — ปักด้วยเทส

**ที่เก็บอันดับสุดท้ายของทัวร์นาเมนต์ และ RPC ประกาศแชมป์**

LSN-0030 ตัดสินว่า **เจ้าภาพเป็นคนยืนยันอันดับสุดท้าย** เพราะระบบคำนวณเองไม่ได้
— สเปกระบุว่าไม่ทำ bracket จึงไม่มีรูปแบบการแข่งให้ระบบรู้ว่าใครชนะทั้งรายการ

**แต่ LSN-0030 จะไม่ทำให้** เพราะตั๋วนั้นทั้งใบตั้งอยู่บนหลักว่า *ไม่มีฝ่ายไหน
ตัดสินผลได้ฝ่ายเดียว* ส่วนการประกาศแชมป์เป็นการกระทำที่เจ้าภาพทำฝ่ายเดียว
**โดยตั้งใจ** เอาสองอย่างมารวมกันทำให้คนอ่านโค้ดทีหลังเข้าใจผิดว่าการยืนยัน
สองฝั่งเป็นทางเลือก

→ ตั๋วนี้เป็นผู้ใช้เพียงรายเดียวของข้อมูลนั้น จึงต้องทำเอง

**ข้อควรระวังที่ยกมาด้วย:** เจ้าภาพประกาศก๊วนตัวเองเป็นแชมป์ได้
ต้องมีอย่างน้อยหนึ่งแมตช์ที่ `confirmed` ของทีมนั้น และการประกาศต้องเขียน
`audit_logs` และมองเห็นได้จากทุกทีม ไม่ใช่ทำเงียบ ๆ

## Decisions — ตัดสิน 23 ก.ย. 2569

### Open Question 1 → แชมป์มาจากระบบคำนวณ + ขั้นต่ำสี่ก๊วน

สเปกเดิมเสนอให้เจ้าภาพประกาศ เพราะไม่มี bracket ระบบจึงไม่รู้รูปแบบการแข่ง
**แต่ LSN-0046 คำนวณแชมป์จากผลแมตช์ที่ยืนยันแล้วไปแล้ว** และโชว์อยู่บนหน้างาน

การให้เจ้าภาพประกาศซ้ำจะสร้างแหล่งความจริงที่สอง และเปิดช่องให้ประกาศก๊วนตัวเอง
เป็นแชมป์โดยไม่เคยลงแข่ง ซึ่งตั๋วเองก็เขียนเตือนไว้ ขั้นต่ำสี่ก๊วนกัน badge
ระดับ elite เฟ้อจากงานสองก๊วนที่เพื่อนผลัดกันเป็นแชมป์

**ผลพวง:** กติกาแชมป์ย้ายจาก TypeScript ไปอยู่ใน SQL ทั้งหมด หน้าจอเรียก
`tournament_standings()` แทนการคิดเอง — LSN-0046 คิดใน TS เพราะตอนนั้นมีผู้ใช้
รายเดียว ตั๋วนี้เพิ่มผู้ใช้รายที่สองคือการให้ badge เหตุผลเดิมจึงหมดอายุ

### Open Question 2 → คิดใหม่ทั้งชุด ถอนได้

แพตเทิร์นเดียวกับ `recompute_player_skill` (LSN-0031) ถ้าผลแมตช์ถูกยกเลิก
badge ที่อิงผลนั้นต้องหายตาม ไม่งั้นงานเดียวจะมีแชมป์สองคน

**แต่ไม่ใช่ลบทิ้งแล้วใส่ใหม่** เพราะ `awarded_at` ต้องไม่ขยับ จึงทำสองจังหวะ:
ใส่ใบใหม่ด้วย `do nothing` แล้วค่อยลบใบที่ไม่เข้าเกณฑ์แล้ว

### Open Question 3 → ผู้ใช้ที่ล็อกอินแล้วเห็นของกันและกันได้

ไม่ขัดกับ LSN-0023 ที่ปิด *รายชื่อสมาชิกก๊วน* จากคนนอก เพราะ badge เป็นผลงาน
ไม่ใช่รายชื่อ และ LSN-0050 ตรวจแล้วว่าค่าเฉลี่ยความประทับใจก็เปิดให้ผู้ใช้ทุกคน
อยู่แล้ว badge ที่ไม่มีใครเห็นเสียเหตุผลของการมีอยู่ไปครึ่งหนึ่ง

### `manners >= 4` สำหรับ `05-fair-play`

สเปกไม่ได้กำหนดเกณฑ์คะแนนไว้ บอกแค่ว่า "ได้รับการชื่นชม" การให้ badge
น้ำใจนักกีฬาจากคะแนนมารยาท 1 เต็ม 5 คงไม่ใช่สิ่งที่ตั้งใจ จึงตีความว่า 4 ขึ้นไป
**เป็นการตัดสินใจ ไม่ใช่สิ่งที่สเปกบอก** ถ้าใช้จริงแล้วรู้สึกว่าเข้มไป แก้ที่
`recompute_player_badges()` จุดเดียว

## Review Notes — 23 ก.ย. 2569

### เทส `awarded_at` ฉบับแรกเป็นเทสที่ดูเหมือนเฝ้าแต่ไม่ได้เฝ้า

เขียนไว้ว่า "เก็บ awarded_at ไว้ก่อน แล้วคิดซ้ำ แล้วเทียบว่าเท่าเดิม"
ตอน falsify ด้วยการเปลี่ยน `do nothing` เป็น `do update set awarded_at = now()`
**เทสยังเขียว**

เพราะ `now()` คืนเวลาเริ่มทรานแซกชัน ไม่ใช่เวลาปัจจุบัน — pgTAP ห่อทุกอย่างไว้ใน
ทรานแซกชันเดียว ค่าจึงเท่ากันเสมอไม่ว่าโค้ดจะเขียนทับหรือไม่

แก้เป็นย้อน `awarded_at` ไปปี 2020 ซึ่งเป็นค่าที่ `now()` ผลิตไม่ได้ แล้วดูว่ามันรอด
คราวนี้ falsify แล้วแดงตรงข้อที่ควรแดง

### ด่านที่แข็งกว่าที่ AC ขอ

AC ข้อ "`05-fair-play` ไม่ให้เมื่อประเมินตนเอง" — ตอนเขียนเทสพบว่า
`player_impressions` มี CHECK constraint `player_impressions_not_self` อยู่แล้ว
**แถวแบบนั้นแทรกไม่ได้เลย** เทสจึงเปลี่ยนไปปักด่านนั้นด้วย `throws_ok` แทนที่จะ
แทรกแล้วดูว่าได้ badge ไหม ซึ่งเป็นการเฝ้าของที่เกิดขึ้นไม่ได้อยู่แล้ว

(กติกาใน `recompute_player_badges()` ยังตรวจซ้ำอยู่ เพราะสมาชิกก๊วนย้ายได้
หลังให้คะแนนไปแล้ว)

### กับดัก seed ที่เจอเป็นรอบที่สอง

เทส "คู่แข่งจากก๊วนอื่นชื่นชม" แดงตอนแรกเพราะใช้ **แนน** เป็นผู้ให้คะแนน
seed ใส่ แนน ไว้ใน *ทั้งสองก๊วน* กติกา "ห้ามก๊วนเดียวกัน" จึงตัดเธอออกอย่างถูกต้อง
ต้องใช้ **มีน** ซึ่งอยู่ก๊วนเดียว — กับดักเดียวกับที่เจอใน LSN-0049

### บั๊กเก่าที่เจอระหว่างทาง

หน้าโปรไฟล์โชว์ `รุ่น` ด้วย `tierLabel()` เต็ม ๆ ที่ `text-2xl` ในคอลัมน์หนึ่งใน
สาม ตัดบรรทัดเป็น **"P · ตี / ประจำ"** หลุดมาตั้งแต่ LSN-0044 เพราะตอนนั้นผม
ตรวจช่องเลือกกับการ์ด แต่ไม่ได้เปิดหน้าโปรไฟล์ แก้เป็นตัวอักษรตัวใหญ่
ชื่อรุ่นตัวเล็กใต้มัน พร้อมเพิ่ม `tierName()`

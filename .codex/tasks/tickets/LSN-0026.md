# 🟢 LSN-0026 — ก๊วนที่คงอยู่ข้ามครั้ง

**Type:** Feature · **Phase:** 10 · **Status:** Backlog
**Spec:** `.codex/specs/tournaments.md` หัวข้อ Decisions ข้อ 1
**Depends on:** **LSN-0027 (เปลี่ยนคำ ก๊วน→นัด) ต้อง merge ก่อนตั๋วนี้เริ่ม** — ดู Blocking notes

## Goal

ก๊วนกลายเป็น *กลุ่มคน* ที่คงอยู่ข้ามการนัดเล่น ไม่ใช่ชื่อของการนัดเล่นครั้งเดียว
ผู้จัดตั้งนัดใหม่ให้ก๊วนเดิมได้โดยไม่ต้องชวนคนใหม่ทุกครั้ง

## Context

ตรวจฐานข้อมูลจริงแล้ว **ไม่มีตาราง `groups` / `teams` / `tournaments` เลย** และ
`sessions` ไม่มีคอลัมน์ไหนผูกนัดนี้กับนัดหน้า (ไม่มี `recurring`, `group`, `parent`,
`series`) — "ก๊วน" ในระบบวันนี้คือ `sessions` หนึ่งแถว = การนัดเล่นหนึ่งครั้ง

ตั๋วนี้เป็นใบแรกของทิศทางทัวร์นาเมนต์ และ **มีคุณค่าของตัวเองตั้งแต่วันแรก
แม้ทัวร์นาเมนต์จะไม่เกิดขึ้นเลย** — ผู้จัดก๊วนแบดประจำตั้งนัดสัปดาห์หน้าได้
โดยไม่ต้องไปตามชวนทีละคนในกลุ่ม LINE ซ้ำทุกอาทิตย์

**ของที่ใช้ซ้ำได้:** `sessions.public_code` มีกลไกสร้างโค้ดอยู่แล้วคือ
`generate_session_code()` และ trigger `sessions_assign_code()` ลิงก์เชิญเข้าก๊วน
ใช้รูปแบบเดียวกันได้ ไม่ต้องคิดใหม่

## Scope

- ตาราง `groups` และ `group_members`
- `sessions.group_id` **nullable** — นัดผูกกับก๊วนก็ได้ ไม่ผูกก็ได้
- สร้างก๊วน · เชิญด้วยลิงก์ · เข้าร่วม · ออกจากก๊วน
- ตั้งนัดจากก๊วน แล้วสมาชิกในก๊วนได้รับแจ้งเตือน
- หน้ารายการก๊วนของฉัน และหน้าก๊วนหนึ่งก๊วน

## Non-goals

- ไม่ทำทัวร์นาเมนต์ · ไม่ทำคะแนนฝีมือ · ไม่ทำเพื่อน — เป็นตั๋วถัดไปตาม spec
- ไม่ทำนัดซ้ำอัตโนมัติตามตาราง (recurring schedule) — ตั๋วนี้แค่ทำให้*กลุ่มคน*คงอยู่
  ส่วนการตั้งนัดยังกดเอง
- ไม่ทำแชตในก๊วน — LINE ทำหน้าที่นั้นอยู่แล้วและดีกว่า
- ไม่ทำรูปปกก๊วน ไม่ทำบทบาทมากกว่า owner/member
- ไม่บังคับว่าต้องมีก๊วนก่อนถึงตั้งนัดได้

## Decisions — ตัดสินแล้ว

### 1. ก๊วนเป็นของ **ไม่บังคับ**

`sessions.group_id` เป็น nullable และการตั้งนัดแบบไม่มีก๊วนต้องใช้ได้เหมือนเดิมทุกอย่าง

เหตุผล: คุณสมบัติที่เป็นหัวใจของโปรดักต์คือ **ลิงก์เดียวที่ใครก็กดเข้ามาได้โดยไม่ต้อง
สมัครอะไรก่อน** ถ้าบังคับให้มีก๊วนก่อน จะเพิ่มขั้นตอนก่อนถึงคุณค่าแรก ซึ่งเป็นสิ่งที่
เอกสารแนวคิดเขียนไว้ว่าตั้งใจหลีกเลี่ยง

### 2. ลบก๊วนแล้วนัดเก่าต้องไม่หาย

`sessions.group_id` ใช้ `on delete set null` และก๊วนใช้ **archive ไม่ใช่ลบจริง**

เหตุผล: นัดหนึ่งนัดมีเงิน การจ่าย การคืนเงิน และใบสรุปผูกอยู่ ประวัติเหล่านั้นต้อง
อธิบายได้ต่อให้ก๊วนเลิกไปแล้ว

### 3. เจ้าของก๊วนคนเดียวใน v1

`group_members.role` เป็น `owner | member` และมี owner ได้คนเดียวต่อก๊วน
ผู้ร่วมเป็นเจ้าของหลายคนเป็นงานคนละใบ เพราะเปิดคำถามเรื่องใครลบใครได้

### 4. คนหนึ่งอยู่ได้หลายก๊วน

ไม่มีข้อจำกัด — คนเล่นแบดหลายก๊วนเป็นเรื่องปกติ และเป็นสิ่งที่ทำให้
"เพิ่มเพื่อนจากก๊วนอื่น" ในตั๋วถัดไปมีความหมาย

## Design

```sql
create table public.groups (
  id            uuid primary key default gen_random_uuid(),
  public_code   text not null unique,        -- ลิงก์เชิญ ใช้รูปแบบเดียวกับ sessions
  name          text not null,
  sport_id      uuid not null references public.sports(id),
  home_district text,
  created_by    uuid not null references public.profiles(id),
  archived_at   timestamptz,                 -- ไม่ลบจริง
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);

create table public.group_members (
  group_id  uuid not null references public.groups(id) on delete cascade,
  user_id   uuid not null references public.profiles(id) on delete cascade,
  role      text not null check (role in ('owner', 'member')),
  joined_at timestamptz not null default now(),
  primary key (group_id, user_id)
);

-- เจ้าของคนเดียวต่อก๊วน
create unique index groups_single_owner
  on public.group_members (group_id) where role = 'owner';

alter table public.sessions
  add column if not exists group_id uuid references public.groups(id) on delete set null;
```

## Acceptance Criteria

- [ ] สร้างก๊วนแล้วผู้สร้างกลายเป็น `owner` โดยอัตโนมัติ — ปักด้วยเทส
- [ ] ก๊วนหนึ่งก๊วนมี `owner` ได้คนเดียว การเพิ่มคนที่สองเป็น owner ถูกปฏิเสธ
      ที่ระดับฐานข้อมูล — ปักด้วยเทส
- [ ] เข้าร่วมก๊วนผ่านลิงก์ `public_code` ได้ และเข้าซ้ำไม่สร้างแถวซ้ำ — ปักด้วยเทส
- [ ] สมาชิกออกจากก๊วนได้ · **เจ้าของออกไม่ได้** จนกว่าจะโอนหรือ archive ก๊วน — ปักด้วยเทส
- [ ] **ตั้งนัดโดยไม่มีก๊วนยังทำได้เหมือนเดิมทุกอย่าง** — ปักด้วยเทส
      ข้อนี้คือข้อที่กันไม่ให้ตั๋วนี้ทำลายทางเข้าหลักของโปรดักต์
- [ ] ตั้งนัดจากก๊วน แล้วสมาชิกทุกคนได้ `notifications` **คนละหนึ่งแถว**
      ไม่รวมผู้ตั้งเอง — ปักด้วยเทส
- [ ] archive ก๊วนแล้วนัดเก่ายังอยู่ครบและเปิดดูได้ — ปักด้วยเทส
- [ ] คนนอกก๊วนอ่าน `group_members` ตรง ๆ ไม่ได้ — ปักด้วย pgTAP
- [ ] pgTAP ของ LSN-0019/0020/0021/0022/0023 ยังเขียวโดยไม่ต้องแก้เทส
- [ ] การสร้าง เข้าร่วม ออก และ archive เขียน `audit_logs`
- [ ] ไม่มี UI ที่กดแล้วไม่ทำอะไร

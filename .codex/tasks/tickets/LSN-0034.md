# 🟢 LSN-0034 — หน้าแรกต้องขายทัวร์นาเมนต์ ไม่ใช่การตั้งนัด

**Type:** Feature · **Phase:** 10 · **Status:** Done
**Source:** `docs/product-concept.md` — "ทำไมทัวร์นาเมนต์คือพาดหัว ไม่ใช่ฟีเจอร์ต่อท้าย"
**Depends on:** LSN-0032 (หน้าสร้างทัวร์นาเมนต์) — merge แล้ว ปุ่มจึงมีที่ให้ไปจริง

## Goal

ให้หน้าแรกเล่าเรื่องเดียวกับที่โปรดักต์ตัดสินไปแล้ว — **ก๊วนประจำออกไปเจอก๊วนอื่น
ในทัวร์นาเมนต์ที่จัดกันเองได้** แทนที่จะเล่าเรื่องการตั้งนัดรายครั้งอย่างเดียว

## Context

`docs/product-concept.md` เขียนไว้ชัดตั้งแต่บรรทัดแรกว่าทัวร์นาเมนต์คือพาดหัว
และวางความสัมพันธ์ไว้ว่า **"ก๊วนประจำเป็นฐาน ทัวร์นาเมนต์เป็นปลายทาง"**
ไม่ใช่ของสองอย่างที่แข่งกัน

แต่ `src/app/page.tsx` ยังเป็นหน้าเดิมทั้งหน้า

| ส่วน | เนื้อหาปัจจุบัน |
| --- | --- |
| พาดหัว | "รวมคน จ่ายเงิน **ได้สนาม** จริง ๆ" |
| คำสัญญาสามข้อ | จ่ายครบถึงจอง · ไม่ได้สนามคืนเต็ม · คิวสำรองอัตโนมัติ |
| ขั้นตอนสี่ขั้น | ตั้งนัด → แชร์เข้า LINE → ระบบจองสนามให้ → ยกเลิกคืนเงิน |
| ปุ่มหลัก | "สร้างนัดของคุณ" |

**ไม่มีคำว่าทัวร์นาเมนต์อยู่บนหน้าแรกเลยแม้แต่ที่เดียว**

## Scope

- เขียนพาดหัว คำสัญญา และขั้นตอนใหม่ให้เป็นเรื่องทัวร์นาเมนต์
- คำสัญญาสามข้อเปลี่ยนเป็น **ประตูสามบาน** (ทีมครบ · เงินครบ · คอร์ตยืนยัน)
  ซึ่งเป็นกลไกที่มีอยู่จริงในโค้ดและผู้ใช้เห็นบนหน้าทัวร์นาเมนต์อยู่แล้ว
- **เก็บชั้นนัดประจำไว้** เป็นส่วนรอง พร้อมอธิบายว่ามันคือฐาน ไม่ใช่ของเก่าที่ถูกแทน
- ปุ่มหลักพาไปสร้างทัวร์นาเมนต์ (ล็อกอินแล้วไป `/app/tournaments/new`
  ยังไม่ล็อกอินไป `/auth/sign-up` ตามแพตเทิร์นเดิมของหน้านี้)
- อัปเดต `brand.tagline` และ `metadata.description` ให้ตรงกับเรื่องใหม่
- คงภาษาภาพเดิมทั้งหมด (court motif · hairline · สีแบรนด์ · จังหวะ rise)
  **ตั๋วนี้เปลี่ยนสาร ไม่ได้เปลี่ยนหน้าตา**

## Non-goals

- **ไม่เพิ่มปุ่ม "หาทัวร์นาเมนต์"** — `/discover` ยังไม่แสดงทัวร์นาเมนต์ ปุ่มจะพาไปที่ว่าง
  ซึ่งผิด Definition of Done ข้อ "ไม่มี UI ที่กดแล้วไม่ทำอะไร"
- ไม่แตะ `/discover` และไม่ทำรายการทัวร์นาเมนต์สาธารณะ — เป็นงานแยก
- ไม่เปลี่ยนสีแบรนด์ ฟอนต์ หรือโครงเลย์เอาต์
- ไม่แตะการ์ดสำหรับเจ้าของสนาม

## Acceptance Criteria

- [x] พาดหัวหน้าแรกพูดเรื่องการเจอก๊วนอื่น ไม่ใช่การตั้งนัด
- [x] คำสัญญาสามข้อคือประตูสามบาน และใช้ถ้อยคำเดียวกับที่ผู้ใช้เห็นในแอปจริง
      (`t.tournaments.gateTeams` · `gateMoney` · `gateCourt`) ไม่ใช่คำใหม่ที่ไม่ตรงกับของจริง
- [x] ขั้นตอนบนหน้าแรกตรงกับสิ่งที่แอปทำได้จริงทุกขั้น **ไม่มีขั้นไหนที่ยังทำไม่ได้**
- [x] ปุ่มหลักพาไปหน้าสร้างทัวร์นาเมนต์ได้จริงทั้งตอนล็อกอินและไม่ล็อกอิน
- [x] ยังมีที่ทางให้ชั้นนัดประจำ พร้อมประโยคที่บอกว่ามันคือฐานของทัวร์นาเมนต์
- [x] **ไม่มีคำโฆษณาที่แอปทำไม่ได้** — ทุกประโยคชี้ไปที่กลไกที่มีโค้ดรองรับ
- [x] `brand.tagline` และ `metadata.description` ตรงกับเรื่องใหม่
- [x] เทสเดิมทั้งหมดเขียวโดยไม่ต้องแก้

## Validation

- `npm run lint` · `npx tsc --noEmit` · `npm test` · `npm run test:db` ผ่าน
- ตรวจเบราว์เซอร์ 375×812 และเดสก์ท็อป
  1. ผู้ใช้ที่ยังไม่ล็อกอิน — อ่านหน้าแรกแล้วเข้าใจว่าสินค้านี้ทำอะไร ปุ่มหลักไปหน้าสมัคร
  2. ผู้ใช้ที่ล็อกอินแล้ว — ปุ่มหลักไปหน้าสร้างทัวร์นาเมนต์จริง
- กดทุกลิงก์บนหน้าแรกแล้วต้องไม่มีอันไหนพาไปหน้าว่างหรือ 404

## Decisions

### ใช้ถ้อยคำเดียวกับในแอป ไม่คิดคำโฆษณาใหม่

คำสัญญาบนหน้าแรกต้องเป็นคำเดียวกับที่ผู้ใช้จะเห็นบนหน้าทัวร์นาเมนต์จริง
ถ้าหน้าแรกเขียนว่า "เงินไม่ครบ ไม่เริ่ม" แต่ในแอปเขียนว่า "ทุกทีมจ่ายแล้ว"
ผู้ใช้ต้องแปลเองว่าอันเดียวกันไหม จึงดึงจาก `t.tournaments.*` มาใช้ตรง ๆ

### เก็บชั้นนัดประจำไว้ ไม่ลบทิ้ง

`docs/product-concept.md` เขียนว่ากลไกเก็บเงินที่สร้างเสร็จแล้ว **ไม่ใช่ของเก่า
ที่ถูกแทนที่ แต่เป็นเครื่องยนต์ที่ทำให้ชั้นบนเป็นไปได้** หน้าแรกที่ลบชั้นล่างทิ้ง
จะเล่าเรื่องผิด และทำให้คนที่มาจากลิงก์นัดงงว่ามาผิดที่

## Blocking notes

- ไม่ทับกับตั๋วอื่น — แตะ `src/app/page.tsx`, `src/i18n/th.ts`, `src/app/layout.tsx`
- **ของค้างที่ตั๋วนี้ทำให้เห็นชัดขึ้น:** `/discover` ยังไม่แสดงทัวร์นาเมนต์
  พอหน้าแรกพูดเรื่องทัวร์นาเมนต์แล้ว การไม่มีที่ให้ "ดูงานที่เปิดรับ" จะยิ่งสะดุด
  ควรเปิดตั๋วแยกต่อจากนี้

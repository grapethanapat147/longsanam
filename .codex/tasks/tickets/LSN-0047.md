# 🟢 LSN-0047 — E2E smoke test เดินเส้นทางคลิกจริง

**Type:** Feature · **Phase:** 11 · **Status:** Done
**Source:** ของที่ต้องปิดก่อน pilot ข้อ 2

## ปัญหา

บั๊กสี่ตัวที่เจอเมื่อ 19 ก.ย. (LSN-0044 · LSN-0045) อยู่นอกสายตาของเทสที่มีอยู่
**ทั้ง pgTAP 245 ข้อและ vitest 174 ข้อ** เพราะไม่มีชุดไหนเดินเส้นทางที่ผู้ใช้เดินจริง

| บั๊ก | ทำไมเทสเดิมไม่เห็น |
| --- | --- |
| หน้ารายการทัวร์นาเมนต์ว่างเปล่าตลอด | เป็นเรื่องของ PostgREST embed ไม่ใช่ของฐานข้อมูลหรือของฟังก์ชันบริสุทธิ์ |
| ยืนยันผลแมตช์ใช้ไม่ได้เลย | `safeupdate` preload ที่บทบาท `authenticator` เท่านั้น pgTAP รันในสิทธิ์ `postgres` |
| ประตูจ่ายเงินตอบไม่เหมือนกันตามคนดู | ต้องมีผู้ใช้สองคนดูหน้าเดียวกันถึงจะเห็น |
| ปุ่มลัดกำหนดปิดรับสมัครคลาดไปหนึ่งวัน | ตรรกะอยู่ในคอมโพเนนต์ ไม่มีใครเรียกมันนอกจากเบราว์เซอร์ |

## Scope

- `@playwright/test` + `playwright.config.ts` + `e2e/`
- เส้นทางหลักหนึ่งรอบ ครอบคลุมทุกบั๊กข้างบน
- `npm run e2e` (รีเซ็ตฐานข้อมูลก่อน) · `npm run e2e:only`
- `npm run test:db` รีเซ็ตก่อนเช่นกัน — ดูหัวข้อถัดไป

## Decisions

### รันกับ production build ไม่ใช่ dev server

ใช้เวลาหาอยู่นานพอควร: dev server ของ Next 16 ในเครื่องนี้ต่อ HMR websocket ไม่ได้
(`ERR_INVALID_HTTP_RESPONSE`) แล้ว**หน้าไม่ hydrate ใน Chromium ของ Playwright**
อาการคือกรอกค่าเข้าช่องได้ (DOM เปลี่ยน) แต่ React ไม่รับรู้ ปุ่มที่ `disabled`
ตามความยาวของค่าจึงไม่มีวันเปิด เทสค้างจนหมดเวลาโดยที่ไม่มีอะไรพังจริง

`npm run build && npm run start` ทำให้ผ่านทันที และตรงกับของที่ผู้ใช้ได้จริงมากกว่า
ใช้พอร์ต 3211 เพื่อไม่ชนกับ dev server ที่เปิดค้างไว้

### ไม่รวมเข้า `npm run verify`

`verify` ต้องเร็วและไม่ต้องพึ่งอะไรนอกเครื่อง E2E ต้องมี Supabase รันอยู่และใช้เวลา
เป็นนาที การรวมกันจะทำให้คนเลิกรัน `verify` ซึ่งแพงกว่าที่ได้

### `test:db` รีเซ็ตฐานข้อมูลก่อนด้วย

เจอตอนรัน E2E แล้วตามด้วย `test:db` — `matches.test.sql` แดงด้วย
`more than one row returned by a subquery` เพราะ E2E ทิ้งทัวร์นาเมนต์และแมตช์ไว้
ไม่ใช่โค้ดพัง แต่เป็น**สองชุดเทสที่ใช้ฐานข้อมูลก้อนเดียวกันโดยไม่มีใครรับผิดชอบ
ความสะอาด** ทางแก้คือให้ทั้งสองชุดเริ่มจากชุด seed เสมอ (`test:db:only` ไว้ใช้ตอน
รู้ว่าฐานข้อมูลสะอาดอยู่แล้ว)

### เทสต้องการฐานข้อมูลที่เพิ่ง seed และประกาศเรื่องนั้นเอง

ข้อแรกของเทสเช็กว่า มีน **ยังไม่มีก๊วนของตัวเอง** ซึ่งเป็นทั้งกติกาที่เฝ้าและ
ตัวเช็กเงื่อนไขตั้งต้น ถ้าแดงจะมีข้อความบอกตรง ๆ ว่าให้ใช้ `npm run e2e`

## Review Notes — 20 ก.ย. 2569

### เทสฉบับแรกของผมเป็น "เทสที่ดูเหมือนเฝ้าแต่ไม่ได้เฝ้า"

ตอน falsify บั๊ก safeupdate เทสกลับแดงที่ขั้น **ตารางคะแนน** แทนที่จะแดงที่ขั้น
**ยืนยันผล** สาเหตุคือผมเขียน `getByText('ยืนยันแล้ว')` แบบ substring ซึ่งไป
แมตช์กับป้ายประตู **"คอร์ตยืนยันแล้ว"** ที่อยู่บนหน้าเดียวกัน

ถ้าไม่ได้ falsify ผมจะส่งเทสที่ผ่านตอนการยืนยันล้มเหลวไปเลย — รูปแบบเดียวกับ
LSN-0022 · LSN-0035 · LSN-0045 แก้ด้วย `{ exact: true }` พร้อมคอมเมนต์บอกเหตุผล
และเทียบข้อความ error เต็มประโยคแทนการจับคำว่า "เกิดข้อผิดพลาด" เฉย ๆ

### ของที่ยังไม่ได้ทำ

- ยังไม่ต่อเข้า CI — repo มีแค่ `sweep.yml` ไม่มี workflow รันเทส และ E2E ต้องมี
  Supabase service ซึ่งเป็นงานของตัวเอง
- ชุดนี้เดินเส้นทางเดียว ไม่ได้ครอบคลุมฝั่งก๊วน (ตั้งนัด · จ่าย · เช็กอิน · ใบสรุป)

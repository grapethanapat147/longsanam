ตั๋วนี้ทำให้คำสัญญาเป็นจริงก่อน ตั๋วนั้นค่อยพูด

## Scope

- หน้าใหม่สำหรับสร้างทัวร์นาเมนต์ ตามแพตเทิร์นของ `src/app/organizer/new/page.tsx`
  (server component โหลดข้อมูล → ส่งให้ client component ที่ถือฟอร์ม)
- ช่องที่ต้องมี ตรงกับ `createTournamentAction` เป๊ะ: ก๊วนเจ้าภาพ · ชื่อรายการ ·
  รุ่น (`N` `S` `P` `C` `B` `A`) · เริ่ม · จบ · ปิดรับสมัคร · ขั้นต่ำทีม ·
  สูงสุดทีม (ไม่บังคับ) · ค่าสมัครต่อก๊วน
- เลือกก๊วนเจ้าภาพได้เฉพาะก๊วนที่ผู้ใช้ **เป็นเจ้าของ** เพราะ `create_tournament`
  เช็ค `is_group_owner()` ถ้าส่งก๊วนที่ไม่ได้เป็นเจ้าของจะได้ `not_owner`
- ทางเข้าจากหน้า `/app/tournaments` — ตอนนี้หน้านั้นมีแต่รายการกับ `EmptyState`
  ที่เขียนว่า "สร้างของก๊วนคุณเอง" แต่ไม่มีปุ่มให้กด
- คนที่ยังไม่มีก๊วนที่ตัวเองเป็นเจ้าของ ต้องเจอทางออกที่ชัด ไม่ใช่ฟอร์มที่กดแล้วพัง
- หลังสร้างเสร็จ พาไปหน้ารายละเอียดงาน และให้เห็นลิงก์ `/t/<code>` สำหรับแชร์

## Decisions — ตัดสินแล้ว 18 ก.ย. 2569 (ทำตามข้อเสนอทั้งสามข้อ)

### 1. หน้าสร้างอยู่ path ไหน

`/organizer/tournaments/new` เข้าชุดกับ `/organizer/new` ที่เป็นหน้าสร้างนัด
หรือ `/app/tournaments/new` เข้าชุดกับหน้ารายการที่มันเกิดมาจาก

**ผมเสนอ `/app/tournaments/new`** เพราะทัวร์นาเมนต์ผูกกับ "ก๊วนของฉัน" ซึ่งอยู่ใต้
`/app` ทั้งหมด ส่วน `/organizer` เป็นโลกของการจัดนัดรายครั้งที่มีวิซาร์ดเลือกคอร์ตของตัวเอง
คนละบริบทกัน

### 2. สร้างแล้วเปิดรับสมัครทันทีเลยไหม

ตอนนี้ RPC แยกสองขั้น: `create_tournament` ได้ `draft` แล้ว `publish_tournament` ถึงเป็น `open`

**ผมเสนอให้คงสองขั้นไว้** แต่หน้าจอต้องบอกชัดว่ายังไม่มีใครสมัครได้จนกว่าจะกดเปิด
เหตุผลคือค่าสมัครกับกำหนดปิดรับเป็นตัวเลขที่ผูกพันเงินคนอื่น ควรมีจังหวะให้ทวนก่อนหนึ่งรอบ
ไม่ใช่กดส่งแล้วประกาศออกไปเลย

### 3. คนที่ยังไม่มีก๊วนของตัวเองเจออะไร

**ผมเสนอ: ไม่ต้องแสดงฟอร์มเลย** แสดงการ์ดอธิบายว่าต้องมีก๊วนก่อน พร้อมปุ่มไป `/app/groups`
ดีกว่าโชว์ฟอร์มที่ช่องเจ้าภาพว่างเปล่าแล้วให้ผู้ใช้ไปเจอ `not_owner` ตอนกดส่ง

### เรื่องที่วินิจฉัยผิดระหว่างทาง

ตอนทดสอบ ปุ่มสร้างขึ้น `disabled` ทั้งที่ช่องมีค่าครบ ดูเหมือนบั๊กของเงื่อนไข
`disabled` แต่ที่จริงเป็น **ข้อจำกัดของวิธีทดสอบ** — การยัดค่าด้วย native setter
ทำให้ DOM มีค่าแต่ React state ยังว่าง พอพิมพ์จริงหนึ่งตัวอักษรปุ่มก็ใช้งานได้ทันที
เปลี่ยนไปใช้ `form_input` ที่อัปเดต React ถูกต้องแล้วทุกอย่างเดินปกติ
**ไม่ได้แก้โค้ดเพราะเรื่องนี้เลย**

### เรื่องที่ตั้งใจไม่ทำ

ฟอร์มตรวจกติกาวันเวลาและจำนวนทีมซ้ำกับ check constraint ของตาราง
**ไม่ใช่การย้ายด่านมาไว้ที่หน้าจอ** — ด่านจริงยังอยู่ที่ตาราง ตรงนี้คือการแปล
error ดิบให้เป็นภาษาที่บอกว่าต้องแก้ตรงไหน ถ้ามีใครยิง RPC ตรงด้วยค่าผิด
ตารางก็ยังปฏิเสธเหมือนเดิม

### ด่านที่ข้ามและเหตุผล

- **`scrutinize` เต็มรูปแบบ** และ **`fullstack-guardian`** — ข้าม ตั๋วนี้
  **ไม่ได้เพิ่ม RPC ไม่แตะ RLS ไม่แตะ migration ไม่แตะเส้นทางเงิน** เป็นการต่อ

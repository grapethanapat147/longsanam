# 🟢 LSN-0032 — หน้าสร้างทัวร์นาเมนต์

**Type:** Feature · **Phase:** 10 · **Status:** Backlog
**Spec:** `.codex/specs/tournaments.md`
**Depends on:** LSN-0026 (ก๊วน) · LSN-0029 (ทัวร์นาเมนต์) — merge เข้า main แล้วทั้งคู่

## Goal

ทำให้ผู้ใช้ **สร้างทัวร์นาเมนต์ของก๊วนตัวเองได้จริงจากหน้าจอ** แล้วเปิดรับสมัคร
เพื่อให้ได้ลิงก์ `/t/<code>` ไปแชร์เข้า LINE

## Context

LSN-0029 สร้างครบทุกชั้นแล้ว **ยกเว้นทางเข้า**

| ชั้น | สถานะ |
| --- | --- |
| RPC `create_tournament` | มีแล้ว `20260919000100_tournaments.sql` |
| Server action `createTournamentAction` | มีแล้ว `src/lib/actions/tournament.ts:54` |
| ข้อความไทยของทุกช่องในฟอร์ม | มีแล้ว `src/i18n/th.ts` (`tournaments.create`, `titleField`, `tierField`, `entryFeeField`, `minTeamsField`, `maxTeamsField`, `deadlineField`, `publish`) |
| **หน้าจอที่เรียก action** | **ไม่มี** |

พิสูจน์: `grep -rn "createTournamentAction" src` เจอที่เดียวคือไฟล์ที่นิยามมันเอง

ผลคือทัวร์นาเมนต์เดียวที่มีอยู่ในระบบตอนนี้คือตัวที่ `supabase/seed.sql` ใส่ไว้
ผู้ใช้จริงสร้างเองไม่ได้เลย และหน้าแรกจึงยังพาดหัวเรื่องทัวร์นาเมนต์ไม่ได้
เพราะปุ่มจะกดไปไม่มีที่ให้ไป ซึ่งผิด Definition of Done ข้อ "ไม่มี UI ที่กดแล้วไม่ทำอะไร"

**ตั๋วถัดไปที่รอตั๋วนี้อยู่: LSN-0034 เขียนหน้าแรกใหม่ให้ขายทัวร์นาเมนต์**
ตั๋วนี้ทำให้คำสัญญาเป็นจริงก่อน ตั๋วนั้นค่อยพูด

## Scope

- หน้าใหม่สำหรับสร้างทัวร์นาเมนต์ ตามแพตเทิร์นของ `src/app/organizer/new/page.tsx`
  (server component โหลดข้อมูล → ส่งให้ client component ที่ถือฟอร์ม)
- ช่องที่ต้องมี ตรงกับ `createTournamentAction` เป๊ะ: ก๊วนเจ้าภาพ · ชื่อรายการ ·
  รุ่น (`N` `S` `P` `C` `B` `A`) · เริ่ม · จบ · ปิดรับสมัคร · ขั้นต่ำทีม ·
  สูงสุดทีม (ไม่บังคับ) · ค่าสมัครต่อก๊วน
- เลือกก๊วนเจ้าภาพได้เฉพาะก๊วนที่ผู้ใช้ **เป็นเจ้าของ** เพราะ `create_tournament`
  เช็ค `is_group_owner()` ถ้าส่งก๊วนที่ไม่ได้เป็นเจ้าของจะได้ `not_owner`
- ทางเข้าจากหน้า `/app/tournaments` — ตอนนี้หน้านั้นมีแต่รายการกับ `EmptyState`
  ที่เขียนว่า "สร้างของก๊วนคุณเอง" แต่ไม่มีปุ่มให้กด
- คนที่ยังไม่มีก๊วนที่ตัวเองเป็นเจ้าของ ต้องเจอทางออกที่ชัด ไม่ใช่ฟอร์มที่กดแล้วพัง
- หลังสร้างเสร็จ พาไปหน้ารายละเอียดงาน และให้เห็นลิงก์ `/t/<code>` สำหรับแชร์

## Non-goals

- ไม่แตะ `/discover` — การให้คนนอกค้นหาทัวร์นาเมนต์เป็นงานแยก
- ไม่แก้หน้าแรก — เป็น LSN-0034
- ไม่แก้ RPC ฝั่งฐานข้อมูล **ยกเว้น** เรื่อง validation ใน Acceptance Criteria ข้อสุดท้าย
- ไม่ทำระบบสาย/ตารางแข่ง — ไม่อยู่ในสเปกของเฟสนี้

## Acceptance Criteria

- [ ] เจ้าของก๊วนสร้างทัวร์นาเมนต์จบได้จากหน้าจอ แล้วได้ `public_code` กลับมา
- [ ] หน้า `/app/tournaments` มีปุ่มเข้าหน้าสร้าง ทั้งตอนมีรายการและตอนว่าง
- [ ] ช่องก๊วนเจ้าภาพแสดงเฉพาะก๊วนที่ผู้ใช้เป็น `owner` เท่านั้น
- [ ] ผู้ใช้ที่ไม่ได้เป็นเจ้าของก๊วนไหนเลย **ไม่เห็นฟอร์มเปล่าที่กดแล้วพัง**
      แต่เห็นข้อความบอกเหตุผลพร้อมลิงก์ไปสร้างก๊วน
- [ ] งานที่เพิ่งสร้างมีสถานะ `draft` และ **ยังไม่มีใครสมัครได้** จนกว่าจะกดเปิดรับสมัคร
- [ ] กดเปิดรับสมัครแล้วสถานะเป็น `open` และลิงก์ `/t/<code>` ใช้ได้จริง
- [ ] ก๊วนเจ้าภาพถูกใส่เป็นทีมแรกอัตโนมัติ (RPC ทำให้แล้ว) และแสดงบนหน้ารายละเอียด
- [ ] **กรอกข้อมูลผิดกติกาแล้วได้ข้อความไทยที่อ่านรู้เรื่อง ไม่ใช่ "เกิดข้อผิดพลาด"**
      กติกาที่ตารางบังคับอยู่แล้วและฟอร์มต้องไม่ปล่อยให้หลุดไปถึง:
      `ends_at > starts_at` · `registration_deadline <= starts_at` ·
      `min_teams >= 2` · `max_teams >= min_teams` · `entry_fee_thb` อยู่ใน 1–100000 ·
      ชื่อรายการไม่ว่างและไม่เกิน 120 ตัว
- [ ] ไม่มี UI ที่กดแล้วไม่ทำอะไร
- [ ] เทสเดิมทั้ง `npm test` และ `npm run test:db` ยังเขียวโดยไม่ต้องแก้เทสเก่า

## Validation

- `npm run lint` · `npx tsc --noEmit` · `npm test` ผ่าน
- `npm run test:db` ผ่าน — ถ้าแตะ RPC ต้องมีเทสใหม่ และ **falsify ทุกเทสที่เพิ่ม**
- ตรวจบนเบราว์เซอร์ 375×812 สี่มุมมอง
  1. เจ้าของก๊วน สร้างงานจนได้ลิงก์แชร์
  2. เจ้าของก๊วน กดเปิดรับสมัคร แล้วเปิด `/t/<code>` เห็นหน้าสมัครจริง
  3. ผู้ใช้ที่ไม่มีก๊วนของตัวเอง เห็นทางออก ไม่ใช่ฟอร์มพัง
  4. กรอกวันจบก่อนวันเริ่ม แล้วต้องได้ข้อความไทยที่บอกเหตุผล

## Open Questions — รอตัดสิน

### 1. หน้าสร้างอยู่ path ไหน

`/organizer/tournaments/new` เข้าชุดกับ `/organizer/new` ที่เป็นหน้าสร้างนัด
หรือ `/app/tournaments/new` เข้าชุดกับหน้ารายการที่มันเกิดมาจาก

**ผมเสนอ `/app/tournaments/new`** เพราะทัวร์นาเมนต์ผูกกับ "ก๊วนของฉัน" ซึ่งอยู่ใต้
`/app` ทั้งหมด ส่วน `/organizer` เป็นโลกของการจัดนัดรายครั้งที่มีวิซาร์ดเลือกคอร์ตของตัวเอง
คนละบริบทกัน

### 2. สร้างแล้วเปิดรับสมัครทันทีเลยไหม

ตอนนี้ RPC แยกสองขั้น: `create_tournament` ได้ `draft` แล้ว `publish_tournament` ถึงเป็น `open`

**ผมเสนอให้คงสองขั้นไว้** แต่หน้าจอต้องบอกชัดว่ายังไม่มีใครสมัครได้จนกว่าจะกดเปิด
เหตุผลคือค่าสมัครกับกำหนดปิดรับเป็นตัวเลขที่ผูกพันเงินคนอื่น ควรมีจังหวะให้ทวนก่อนหนึ่งรอบ
ไม่ใช่กดส่งแล้วประกาศออกไปเลย

### 3. คนที่ยังไม่มีก๊วนของตัวเองเจออะไร

**ผมเสนอ: ไม่ต้องแสดงฟอร์มเลย** แสดงการ์ดอธิบายว่าต้องมีก๊วนก่อน พร้อมปุ่มไป `/app/groups`
ดีกว่าโชว์ฟอร์มที่ช่องเจ้าภาพว่างเปล่าแล้วให้ผู้ใช้ไปเจอ `not_owner` ตอนกดส่ง

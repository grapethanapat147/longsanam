# LSN-0016 — Realtime session updates

**Type:** Feature · **Phase:** 7 · **Status:** Done

## Goal
Headcount, payment state and booking status update on screen without a manual
refresh, so an organizer watching a session fill up sees it happen.

## Approach
Realtime is used as a **change signal, not a data source**: a Postgres change
triggers `router.refresh()`, and the server re-fetches under RLS. Nothing from
the realtime payload is rendered, so the feature cannot leak a row the viewer
would not otherwise be allowed to read.

## Acceptance criteria
- [x] `session_participants`, `sessions`, `bookings`, `waitlist_entries` added
      to the `supabase_realtime` publication.
- [x] A reusable client component subscribes per session and refreshes.
- [x] Wired into the public session page, the organizer dashboard and the
      venue booking inbox.
- [x] Subscriptions are torn down on unmount; no duplicate channels.
- [x] Documented limitation: anonymous viewers get no live events, because
      `anon` has no SELECT on the participation tables.

## Review notes
Two Supabase Realtime behaviours cost real debugging time and are worth
recording, because neither surfaces as an error:

- **The socket does not inherit the page's session.** Without an explicit
  `realtime.setAuth(token)` the subscription is evaluated as `anon`, no matter
  what `@supabase/ssr` has in cookies.
- **A binding on a table the subscriber cannot read kills the whole channel.**
  It is not skipped, and the channel still reports `SUBSCRIBED` — every other
  binding just goes quiet. Isolated with a standalone Node probe: `anon` on
  `sessions` alone delivered events; adding `session_participants` (no SELECT
  grant for `anon`) silenced everything; the same bindings with a token worked.
  Bindings are therefore filtered to what the viewer may actually read.
- `supabase.channel(topic)` returns an existing channel when one is still
  registered, so React's double-invoked effects threw
  "cannot add postgres_changes callbacks after subscribe()". Each connection
  attempt now uses a unique topic.

Verified by changing rows directly in Postgres and watching the page move from
฿400/4 players to ฿300/3 with no navigation and a clean console.

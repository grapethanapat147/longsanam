# LSN-0019 — Pay later, and the credit that backs it

**Type:** Feature · **Phase:** 8 · **Status:** Done
**Spec:** `.codex/specs/pay-later-credit.md`

## Goal
An organizer can hand one named player a seat now and payment later, and the
system does the chasing afterwards instead of the organizer doing it by hand in
the LINE chat. A player who keeps not paying loses the privilege, and nothing
else.

Today the only outcome for an unpaid seat is `payment_expired` and a released
slot. That is right for strangers and wrong for the regular group this product
is built around.

## Constraint this must not break
Only a settled seat counts toward the booking threshold, so `จ่ายครบ ถึงจอง`
stays literally true. The gate lives in `settle_payment()`:
`count(paid_confirmed participants with a paid payment) >= sessions.min_players`.
A `joined_pay_later` participant is not `paid_confirmed`, so it is already
excluded — no change to that function, but a test must pin it, because today the
exclusion is incidental rather than intended.

The consequence must be shown in the grant dialog, not discovered afterwards:
that seat stops counting toward `min_players`, so the session needs one more
paying player to become bookable.

Rejected alternatives, recorded so they are not re-proposed: organizer fronts
the money (turns organizers into lenders), platform fronts it (turns Longsanam
into one).

## Scope
- Organizer-initiated grant and revoke, per participant, gated on credit score.
- Two new `participant_status` values: `joined_pay_later`, `payment_overdue`.
- Pay-later payment rows carry `expires_at = null` so the existing
  `expire_overdue_payments()` skips them untouched.
- New `chase_unpaid_participants()` RPC on the existing five-minute sweep.
- New tables `player_credit` and append-only `credit_events`, with RLS.
- Reminder + credit schedule per the spec: 2h after `ends_at`, three-day grace,
  then −5/day, reminders stop at day 14.
- Score gates pay-later eligibility only. It does not block joining, does not
  block paying up front, and is not a public badge.

## Non-goals
- Automatic pay-later from score alone.
- Blocking session joins on a low score.
- Any fee, interest, or escalating charge. The amount owed stays the amount
  owed.

## Acceptance criteria
- [x] Organizer can grant and revoke pay-later per participant; the grant
      dialog states the resulting paid count against `min_players` and the baht
      that will not arrive before the session.
- [x] The grant control is disabled with a visible reason when the score is
      below `PAY_LATER_MIN_SCORE` (default 70) or the session no longer accepts
      grants. *(rendered check: `disabled: true`, reason
      "เครดิต 50 ต่ำกว่าเกณฑ์ 70")*
- [x] `joined_pay_later` participants are excluded from the `min_players`
      count in `settle_payment()`, pinned by a test.
- [x] `expire_overdue_payments()` never touches a pay-later payment row,
      pinned by a test.
- [x] `chase_unpaid_participants()` moves participants to `payment_overdue`,
      sends reminders on the stated schedule, and is idempotent under a
      five-minute sweep (`last_chased_at`).
- [x] Credit moves exactly as tabulated, floors at 0, caps at 100, and every
      movement writes a `credit_events` row.
- [x] Player sees own score and history; organizer sees scores only for players
      in their own sessions; platform admin sees all. RLS proves each.
      *(12 pgTAP assertions in `supabase/tests/pay_later_rls.test.sql`,
      `npm run test:db`)*
- [x] Every new status transition writes to `audit_logs`.
- [x] LINE push failure or absence never fails the sweep.
      *(real sweep through `/api/cron/expire` with no LINE token: `ok: true`,
      `chasedParticipants: 1`)*

## Validation
- `npm run lint`, `npx tsc --noEmit`, `npm test` pass.
- Unit tests cover the credit arithmetic and the chase schedule as pure
  functions, with no database.
- Migration applied locally and against the cloud project before Review.
- No non-functional UI: the grant control either works or is disabled with its
  reason shown.

## Open questions
- Should a player who owes *this* organizer money be grantable pay-later again
  by that same organizer? Working answer: yes — it is the organizer's call and
  the score already carries the history. Revisit if organizers ask for a hard
  stop.
- `PAY_LATER_MIN_SCORE`, the grace window, the −5/day rate and the 14-day
  cutoff are proposed defaults, not researched ones. They are cheap to change
  later; they are listed here so a reviewer knows they were chosen, not derived.

## Implementation plan

**Goal:** An organizer can grant one named player a seat now and payment later;
the system chases the debt after the session and decays a credit score that
gates nothing but the privilege itself.

**Architecture:** Follow the shape already used by refunds. Decision rules live
in TypeScript as pure functions under `src/lib/domain/` so they are unit-tested
with no database (`tests/*.test.ts`, imported via `@/lib/domain/...`). Postgres
owns transactions and listing: SECURITY DEFINER RPCs list who is due and apply
one state change each. The orchestrator in `src/lib/` joins them, exactly as
`refundAllPaidParticipants` does today.

One deliberate exception to "rules live in TS": the eligibility threshold and
the 0–100 clamp appear in *both* `src/lib/domain/credit.ts` and the SQL. That is
defence in depth, not an oversight — the TS copy decides what the organizer's UI
offers, the SQL copy is the security boundary that a forged request still hits.
Task 5 Step 2 pins that both use 70.

**Tech stack:** Next.js 16 App Router, React 19, TypeScript strict, Supabase
Postgres + RLS, Vitest.

**Conventions this plan follows:** migrations are `supabase/migrations/
YYYYMMDDNNNNNN_name.sql`; server actions are `'use server'` in
`src/lib/actions/`, re-establish the caller with `getCurrentUser()` and call
RPCs through the *user's* client so `auth.uid()` applies; `createAdminClient()`
is only for unattended paths; every transition calls `app_log(...)`.

/**
 * Credit arithmetic.
 *
 * These numbers are chosen, not derived — see the open questions on LSN-0019.
 * They live here as pure functions so the rules are stated once and pinned by
 * tests, rather than being reimplemented in SQL where nothing checks them.
 */

export const CREDIT_MAX = 100;
export const CREDIT_FLOOR = 0;
export const CREDIT_START = 100;
export const PAY_LATER_MIN_SCORE = 70;

/** Days after the session ends before credit starts falling. */
export const GRACE_DAYS = 3;
/** Day at which reminders and credit decay both stop. */
export const CHASE_STOP_DAY = 14;

export const CREDIT_PER_OVERDUE_DAY = -5;
export const CREDIT_PAID_IN_GRACE = 5;
export const CREDIT_SETTLED_LATE = 10;

export function applyDelta(score: number, delta: number): number {
  return Math.min(CREDIT_MAX, Math.max(CREDIT_FLOOR, score + delta));
}

/**
 * The credit charged for one whole day of being overdue. Zero inside the grace
 * window and zero again once chasing stops — past that point the score has said
 * what it has to say, and grinding it lower changes nobody's behaviour.
 */
export function creditDeltaForOverdueDay(dayIndex: number): number {
  if (dayIndex < GRACE_DAYS) return 0;
  if (dayIndex >= CHASE_STOP_DAY) return 0;
  return CREDIT_PER_OVERDUE_DAY;
}

export function isPayLaterEligible(score: number): boolean {
  return score >= PAY_LATER_MIN_SCORE;
}
```

/** Chasing begins two hours after the session ends, not the moment it does. */
export const CHASE_START_HOURS = 2;

const HOUR_MS = 60 * 60 * 1000;
const DAY_MS = 24 * HOUR_MS;

/** Zero on the first chase, then one per whole elapsed day. */
export function overdueDayIndex(endsAt: Date, now: Date): number {
  const start = endsAt.getTime() + CHASE_START_HOURS * HOUR_MS;
  if (now.getTime() < start) return -1;
  return Math.floor((now.getTime() - start) / DAY_MS);
}

export type ChaseInput = { endsAt: Date; lastChasedAt: Date | null; now: Date };
export type ChaseDecision = { shouldChase: boolean; dayIndex: number; creditDelta: number };

/**
 * Whether this participant is due a reminder right now.
 *
 * The sweep runs every five minutes, so the guard that matters is not "is it
 * time" but "have we already done today's". `lastChasedAt` carries that, which
 * is why the decision is a function of it rather than of the clock alone.
 */
export function chaseDecision({ endsAt, lastChasedAt, now }: ChaseInput): ChaseDecision {
  const dayIndex = overdueDayIndex(endsAt, now);
  const idle: ChaseDecision = { shouldChase: false, dayIndex, creditDelta: 0 };

  if (dayIndex < 0) return idle;
  if (dayIndex >= CHASE_STOP_DAY) return idle;
  if (lastChasedAt && overdueDayIndex(endsAt, lastChasedAt) >= dayIndex) return idle;

  return { shouldChase: true, dayIndex, creditDelta: creditDeltaForOverdueDay(dayIndex) };
}
```

create or replace function public.grant_pay_later(p_participant_id uuid)
returns jsonb
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  v_p       record;
  v_session record;
  v_score   integer;
begin
  select * into v_p from public.session_participants where id = p_participant_id;
  if v_p is null then return jsonb_build_object('ok', false, 'reason', 'not_found'); end if;

  select * into v_session from public.sessions where id = v_p.session_id;
  if not public.is_session_organizer(v_session.id) then
    return jsonb_build_object('ok', false, 'reason', 'not_organizer');
  end if;
  if v_session.status in ('completed', 'cancelled') then
    return jsonb_build_object('ok', false, 'reason', 'session_closed');
  end if;
  if v_p.status <> 'joined_pending_payment' then
    return jsonb_build_object('ok', false, 'reason', 'wrong_state');
  end if;

  select coalesce(score, 100) into v_score from public.player_credit where user_id = v_p.user_id;
  if coalesce(v_score, 100) < 70 then
    return jsonb_build_object('ok', false, 'reason', 'credit_too_low', 'score', coalesce(v_score, 100));
  end if;

  update public.session_participants
  set status = 'joined_pay_later',
      pay_later_granted_at = now(),
      pay_later_granted_by = auth.uid()
  where id = p_participant_id;

  -- The debt is real from this moment. expires_at stays null so
  -- expire_overdue_payments() leaves it alone.
  insert into public.payments (participant_id, session_id, user_id, amount_thb, status, expires_at)
  values (p_participant_id, v_p.session_id, v_p.user_id, v_p.amount_due_thb, 'pending', null)
  on conflict do nothing;

  perform public.app_log(auth.uid(), 'session_participant', p_participant_id, v_p.session_id,
    'participant.pay_later_granted', 'joined_pending_payment', 'joined_pay_later', '{}'::jsonb);

  return jsonb_build_object('ok', true);
end;
$$;

create or replace function public.revoke_pay_later(p_participant_id uuid)
returns jsonb
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  v_p record;
begin
  select * into v_p from public.session_participants where id = p_participant_id;
  if v_p is null or v_p.status <> 'joined_pay_later' then
    return jsonb_build_object('ok', false, 'reason', 'wrong_state');
  end if;
  if not public.is_session_organizer(v_p.session_id) then
    return jsonb_build_object('ok', false, 'reason', 'not_organizer');
  end if;

  update public.payments set status = 'expired'
  where participant_id = p_participant_id and status = 'pending';

  update public.session_participants
  set status = case when v_p.payment_due_at <= now()
                    then 'payment_expired'::public.participant_status
                    else 'joined_pending_payment'::public.participant_status end,
      pay_later_granted_at = null,
      pay_later_granted_by = null
  where id = p_participant_id;

  perform public.app_log(auth.uid(), 'session_participant', p_participant_id, v_p.session_id,
    'participant.pay_later_revoked', 'joined_pay_later', 'revoked', '{}'::jsonb);

  return jsonb_build_object('ok', true);
end;
$$;

/** Everyone the sweep might owe a reminder. The decision itself is TypeScript's. */
create or replace function public.list_chaseable_participants()
returns table (
  participant_id uuid,
  user_id        uuid,
  session_id     uuid,
  session_title  text,
  amount_due_thb integer,
  ends_at        timestamptz,
  last_chased_at timestamptz,
  status         public.participant_status,
  line_user_id   text
)
language sql
security definer
set search_path = public, pg_temp
as $$
  select sp.id, sp.user_id, sp.session_id, s.title, sp.amount_due_thb,
         s.ends_at, sp.last_chased_at, sp.status, pc.line_user_id
  from public.session_participants sp
  join public.sessions s on s.id = sp.session_id
  left join public.profile_contacts pc on pc.user_id = sp.user_id
  where sp.status in ('joined_pay_later', 'payment_overdue')
    and s.ends_at + interval '2 hours' <= now()
    and s.ends_at + interval '14 days'  >  now();
$$;

create or replace function public.record_chase(
  p_participant_id uuid,
  p_delta          integer,
  p_reason         text,
  p_title          text,
  p_body           text
) returns jsonb
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  v_p    record;
  v_new  integer;
begin
  select * into v_p from public.session_participants where id = p_participant_id for update;
  if v_p is null then return jsonb_build_object('ok', false, 'reason', 'not_found'); end if;

  if v_p.status = 'joined_pay_later' then
    update public.session_participants set status = 'payment_overdue' where id = p_participant_id;
    perform public.app_log(null, 'session_participant', p_participant_id, v_p.session_id,
      'participant.payment_overdue', 'joined_pay_later', 'payment_overdue', '{}'::jsonb);
  end if;

  update public.session_participants set last_chased_at = now() where id = p_participant_id;

  if p_delta <> 0 then
    insert into public.player_credit (user_id, score) values (v_p.user_id, 100)
    on conflict (user_id) do nothing;

    update public.player_credit
    set score = greatest(0, least(100, score + p_delta))
    where user_id = v_p.user_id
    returning score into v_new;

    insert into public.credit_events (user_id, session_id, delta, reason)
    values (v_p.user_id, v_p.session_id, p_delta, p_reason);
  end if;

  perform public.notify_user(v_p.user_id, v_p.session_id, 'payment_overdue', p_title, p_body, null);

  return jsonb_build_object('ok', true, 'score', v_new);
end;
$$;

### Task 6 — Wire the chase into the existing sweep

**Files:**

```ts
import 'server-only';

import { createAdminClient } from '@/lib/supabase/admin';
import { chaseDecision } from '@/lib/domain/credit';
import { pushLineMessage } from '@/lib/line';

/**
 * Post-session payment chasing.
 *
 * Postgres lists who is in the window; `chaseDecision` decides whether today's
 * reminder has already gone out. Keeping the decision here means the schedule
 * is stated once, in the file the tests read.
 */
export type ChaseResult = { chasedParticipants: number; creditCharged: number };

export async function runPaymentChase(): Promise<ChaseResult> {
  const admin = createAdminClient();
  const result: ChaseResult = { chasedParticipants: 0, creditCharged: 0 };

  const { data, error } = await admin.rpc('list_chaseable_participants');
  if (error) {
    console.error('[chase] list_chaseable_participants failed', error);
    return result;
  }

  const now = new Date();

  for (const row of (data ?? []) as {
    participant_id: string;
    session_title: string;
    amount_due_thb: number;
    ends_at: string;
    last_chased_at: string | null;
    line_user_id: string | null;
  }[]) {
    const decision = chaseDecision({
      endsAt: new Date(row.ends_at),
      lastChasedAt: row.last_chased_at ? new Date(row.last_chased_at) : null,
      now,
    });
    if (!decision.shouldChase) continue;

    const { error: chaseError } = await admin.rpc('record_chase', {
      p_participant_id: row.participant_id,
      p_delta: decision.creditDelta,
      p_reason: `overdue_day_${decision.dayIndex}`,
      p_title: 'ยังค้างชำระค่าก๊วน',
      p_body: `ก๊วน "${row.session_title}" จบแล้ว ยอดค้าง ฿${row.amount_due_thb}`,
    });

    if (chaseError) {
      console.error('[chase] record_chase failed', row.participant_id, chaseError);
      continue;
    }

    result.chasedParticipants += 1;
    if (decision.creditDelta !== 0) result.creditCharged += 1;

    // LINE is an extra channel, never a required one. record_chase has already
    // written the in-app notification, so a dead token must not cost us the
    // sweep — pushLineMessage returns a result rather than throwing.
    if (row.line_user_id) {
      const push = await pushLineMessage({
        lineUserId: row.line_user_id,
        text: `ก๊วน "${row.session_title}" จบแล้ว ยอดค้าง ฿${row.amount_due_thb}`,
      });
      if (!push.ok && push.reason === 'request_failed') {
        console.warn('[chase] LINE push failed', row.participant_id, push.detail);
      }
    }
  }

  return result;
}
```

## Review verdict — NEEDS FIX, fixed

`scrutinize` traced the change end to end and found one blocker, now fixed in

touch payments and auth, is not available in this environment; `scrutinize`

### Blocker (fixed): a declined card made a pay-later debt unpayable forever

`settle_payment()` marks a failed charge's row `failed` and leaves the
participant alone. The pay-later branch of `payForSlotAction` looked only for a
`pending` row, and `start_payment()` refuses a pay-later participant twice over
— wrong status, and a `payment_due_at` that has passed by design. So after one
decline there was no live row to settle against and no way to make one. The
player could never pay; only an organizer revoke could unstick it, and only
before the original deadline.

Proven, not argued: granting then settling with `p_succeeded = false` left
`participant = joined_pay_later` with a single `failed` payment row and zero
`pending` rows — exactly what the action queries for.

The fix is `open_pay_later_payment()`, which returns the live row when there is
one and opens a fresh one when there is not. Verified end to end: decline →
retry → `expires_at = NULL` on the new row → settle → `paid_confirmed`.

`MOCK_PAYMENT_FAILURE_RATE` defaults to `0`, so no ordinary test path reaches a
decline. With a real Thai gateway, declines are routine. This would have shipped.

### Accepted as designed, not fixed

Credit decays per *chase that ran*, not per elapsed day. If the sweep were down
for a week, the player would be charged once on its return, not seven times.
The spec's table says "−5 per day", so this is a divergence — but the more
defensible rule is the one implemented: no reminder, no charge. Players should
not pay for our downtime. The spec table should be read as "per day we told
them", and `chaseDecision` is where that is enforced.

- `record_chase()` returns `"score": null` when `p_delta = 0`, because `v_new`

- `grant_pay_later()` adopts an existing payment row without re-checking that
  its `amount_thb` still matches `session_participants.amount_due_thb`. There is
  no path that edits the per-person amount after a player joins, so the two

## Review addendum — RLS, and a second leak the tests caught

`npm run test:db` runs 12 pgTAP assertions against the local database. Writing
them was worth it before the first one ran: reading `shares_session_with` to
justify the policy showed it does not mean what the policy name claimed.

Its first clause is true for **any co-participant** — it exists so teammates can
see each other's display names. Borrowing it for `player_credit` meant every
player in a session could read every teammate's credit score. Its second clause
is true for any organizer of a *public* session, which made every organizer's
own score world-readable. Both failed on the first run (tests 3 and 5), exactly
as predicted, and both are now fixed by a dedicated
`organizes_session_with(uuid)` helper that means only what its name says.

A display name and a score that encodes "this person does not pay what they owe"
do not deserve the same visibility rule. Reusing the helper looked like good
practice and was the bug.

The write path is pinned too: `authenticated` cannot insert into either table
and cannot raise its own score, because neither table carries an insert, update
or delete policy at all.

Verified after a full `npm run db:reset`, so the fix lives in the migration file
rather than in a hand-applied patch.

## Review addendum 2 — the sweep found a bug that reading never would

Running the real sweep against a staged overdue debt produced this, which is
correct on every line and wrong as a whole:

```
"strandedSessions": 1, "refundedPlayers": 2, "refundedThb": 200,
"chasedParticipants": 1, "creditCharged": 1
```

The session reached its start time without a court, so the platform cancelled it
and refunded the two players who had paid — the promise the landing page makes
as ไม่ได้สนาม คืนเต็ม. In the same sweep, the pay-later player was chased for
money and charged five credit. Paid players were made whole; the one who had not
paid yet was left holding the only bill for a session that never happened
because *we* could not find a court. `list_chaseable_participants()` filtered on
`ends_at` and never looked at `sessions.status`.

Fixed with a trigger on `sessions`, `void_pay_later_on_session_end()`: a session

remember to call this.

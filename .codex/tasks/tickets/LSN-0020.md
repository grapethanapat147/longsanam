# LSN-0020 — Check-in at the venue

**Type:** Feature · **Phase:** 8 · **Status:** Review
**Spec:** `.codex/specs/check-in.md`
**Depends on:** LSN-0019 (credit tables, chase sweep, cancel-voids-debt trigger)

## Goal
Record who actually turned up. LSN-0019 made a debt real and chased it, but
nothing in the system knows whether the player was there — so a reminder cannot
say "you were", and a pay-later player who took a seat, never came and never
cancelled looks identical to an honest late payer.

Attendance is the evidence the credit system was missing. ตีแบด has check-in
and spends it on bonus points; Longsanam needs it for something heavier.

## Decisions already made
- **The organizer marks attendance, not GPS self-check-in.** They already know
  who came, the session page is already open on their phone, and a tap per name
  beats a geofence with none of the spoofing questions.
- **Window:** `starts_at − 30 min` to `ends_at + 2 h` — the same moment the
  chase begins. Outside it the control renders disabled with the reason shown.
- **Credit, narrowly.** One new event only, where behaviour is unambiguous:
  a pay-later seat with no check-in and no cancel at `ends_at + 2h` is charged
  **−10** (`no_show_unpaid`). A paid no-show is charged nothing — they paid, and
  their absence cost only themselves. Never on a `cancelled` or
  `booking_failed` session; `void_pay_later_on_session_end()` already guards
  that transition and this must reuse the same rule.

## Scope
- `session_participants.checked_in_at timestamptz`, `checked_in_by uuid`,
  `no_show_marked_at timestamptz` (idempotency for the sweep).
- RPC `set_check_in(p_participant_id, p_present boolean)` — organizer only,
  idempotent, writes `audit_logs`.
- RPC `mark_no_shows()` on the existing five-minute sweep, after
  `complete_finished_sessions()`.
- Chase reminders include the check-in time when one exists:
  "คุณเช็คอินเมื่อ 19:05 · ยอดค้าง ฿193".
- Organizer session page: a per-row check-in toggle inside the window, disabled
  with reason outside it.

## Non-goals
- GPS or QR self-check-in by players.
- Attendance history views or streaks.
- Any change to paid players' money.

## Acceptance criteria
- [x] Organizer can mark and unmark each participant inside the window; the
      control is disabled with a visible reason outside it.
- [x] `set_check_in` refuses non-organizers and writes `audit_logs`.
- [x] A pay-later seat with no check-in and no cancel is charged −10 exactly
      once, with a `credit_events` row, and never on a cancelled session.
- [x] A paid no-show is charged nothing, pinned.
- [x] Chase reminders include the check-in time when one exists.
- [x] `mark_no_shows()` is idempotent under the five-minute sweep, pinned.

## Validation
- `npm run lint`, `npx tsc --noEmit`, `npm test` pass.
- pgTAP in `supabase/tests/` covers the window, the no-show charge, the
  cancelled-session guard, and idempotency. `npm run test:db` passes.
- Migration applies from scratch via `npm run db:reset`.
- No non-functional UI: the check-in control either works or is disabled with
  its reason shown.

## Open questions
- Whether −10 for an unpaid no-show is the right size relative to LSN-0019's
  −5/day. It is proposed, not derived; it lives as a named constant in
  `src/lib/domain/credit.ts` so it is a one-line change with tests attached.

## Implementation plan

**Goal:** Record who turned up, and use that record for exactly one thing —
charging a pay-later seat that never came and never cancelled.

**Architecture:** The same shape LSN-0019 settled on. The window rule and the
no-show charge live in `src/lib/domain/credit.ts` as pure functions the Vitest
suite pins. Postgres owns the writes: `set_check_in` for the organizer's tap,
`mark_no_shows` for the sweep. The organizer's control is a client component
next to `PayLaterControl` in the participant row.

**Ordering is the whole risk of this ticket.** `runLifecycleSweeps` currently
runs four RPCs in a `Promise.all`, and *then* loops over stranded sessions,
cancelling them and refunding. A session that is about to be cancelled in that
loop still looks like an ordinary finished session while the `Promise.all` is
running. So `mark_no_shows()` must be called **after** the stranded loop, beside
`runPaymentChase()` — and must *also* exclude cancelled and `booking_failed`
sessions itself. Two guards, because LSN-0019 already shipped one bug of exactly
this shape: the sweep refunding paid players while billing the unpaid one.

**Tech stack:** Next.js 16 App Router, React 19, TypeScript strict, Supabase
Postgres + RLS, Vitest, pgTAP.

```ts
/**
 * Attendance.
 *
 * The window closes where the chase opens (`CHASE_START_HOURS`), so there is
 * never a moment when someone is being reminded about a debt whose attendance
 * the organizer could still be recording.
 */

export const CHECK_IN_OPENS_MINUTES_BEFORE = 30;

/** A pay-later seat that never came and never cancelled. */
export const CREDIT_NO_SHOW_UNPAID = -10;

export type CheckInWindow = {
  opensAt: Date;
  closesAt: Date;
  isOpenAt: (now: Date) => boolean;
};

export function checkInWindow(startsAt: Date, endsAt: Date): CheckInWindow {
  const opensAt = new Date(startsAt.getTime() - CHECK_IN_OPENS_MINUTES_BEFORE * 60 * 1000);
  const closesAt = new Date(endsAt.getTime() + CHASE_START_HOURS * 60 * 60 * 1000);
  return {
    opensAt,
    closesAt,
    isOpenAt: (now) => now >= opensAt && now < closesAt,
  };
}

/**
 * What a missed session costs. Only the unpaid, uncancelled case charges
 * anything: a paid player who did not come has already paid for the seat they
 * wasted, and taking credit from them too would be charging twice for one
 * absence.
 */
export function noShowDelta(status: string, checkedIn: boolean): number {
  if (checkedIn) return 0;
  if (status !== 'joined_pay_later' && status !== 'payment_overdue') return 0;
  return CREDIT_NO_SHOW_UNPAID;
}
```

```sql
--
-- The organizer marks attendance. Not GPS: they already know who came, the page
-- is already open on their phone, and a tap per name raises no question of
-- spoofing.

alter table public.session_participants
  add column if not exists checked_in_at     timestamptz,
  add column if not exists checked_in_by     uuid references public.profiles (id),
  add column if not exists no_show_marked_at timestamptz;

comment on column public.session_participants.no_show_marked_at is
  'Idempotency guard for mark_no_shows() under the five-minute sweep.';

create index if not exists session_participants_no_show_idx
  on public.session_participants (session_id, no_show_marked_at)
  where status in ('joined_pay_later', 'payment_overdue');

create or replace function public.set_check_in(
  p_participant_id uuid,
  p_present        boolean
) returns jsonb
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  v_p       public.session_participants%rowtype;
  v_session public.sessions%rowtype;
begin
  select * into v_p from public.session_participants where id = p_participant_id for update;
  if v_p.id is null then
    return jsonb_build_object('ok', false, 'reason', 'not_found');
  end if;

  select * into v_session from public.sessions where id = v_p.session_id;

  if not public.is_session_organizer(v_session.id) then
    return jsonb_build_object('ok', false, 'reason', 'not_organizer');
  end if;

  -- The window mirrors checkInWindow() in src/lib/domain/credit.ts. Duplicated
  -- deliberately, like the pay-later threshold: the TS copy decides what the UI
  -- offers, this copy is the boundary a forged request still hits.
  if now() < v_session.starts_at - interval '30 minutes'
     or now() >= v_session.ends_at + interval '2 hours' then
    return jsonb_build_object('ok', false, 'reason', 'outside_check_in_window');
  end if;

  update public.session_participants
  set checked_in_at = case when p_present then now() else null end,
      checked_in_by = case when p_present then auth.uid() else null end
  where id = p_participant_id;

  perform public.app_log(auth.uid(), 'session_participant', p_participant_id, v_p.session_id,
    case when p_present then 'participant.checked_in' else 'participant.check_in_cleared' end,
    v_p.status::text, v_p.status::text,
    jsonb_build_object('present', p_present));

  return jsonb_build_object('ok', true, 'present', p_present);
end;
$$;

revoke execute on function public.set_check_in(uuid, boolean) from public;
grant execute on function public.set_check_in(uuid, boolean) to authenticated;
```

```sql
-- ---------------------------------------------------------------------------
-- Marking no-shows.
--
-- Two guards against charging someone for a session that is being cancelled in
-- the same sweep: this function skips cancelled and booking_failed sessions,
-- and its caller runs after the stranded-session loop rather than inside the
-- Promise.all. LSN-0019 shipped a bug of exactly this shape — the sweep
-- refunding paid players while billing the unpaid one — and one guard is not
-- enough for a race that produces a wrong charge against a real person.
-- ---------------------------------------------------------------------------

create or replace function public.mark_no_shows()
returns jsonb
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  v_row   record;
  v_count integer := 0;
  v_new   integer;
begin
  for v_row in
    select sp.id, sp.user_id, sp.session_id, sp.status
    from public.session_participants sp
    join public.sessions s on s.id = sp.session_id
    where sp.status in ('joined_pay_later', 'payment_overdue')
      and sp.checked_in_at is null
      and sp.no_show_marked_at is null
      and sp.user_id is not null
      and s.status not in ('cancelled', 'booking_failed')
      and s.ends_at + interval '2 hours' <= now()
    for update of sp skip locked
  loop
    update public.session_participants
    set no_show_marked_at = now()
    where id = v_row.id;

    insert into public.player_credit (user_id, score) values (v_row.user_id, 100)
    on conflict (user_id) do nothing;

    update public.player_credit
    set score = greatest(0, least(100, score - 10))
    where user_id = v_row.user_id
    returning score into v_new;

    insert into public.credit_events (user_id, session_id, delta, reason)
    values (v_row.user_id, v_row.session_id, -10, 'no_show_unpaid');

    perform public.app_log(null, 'player_credit', v_row.user_id, v_row.session_id,
      'credit.no_show', null, v_new::text, jsonb_build_object('delta', -10));

    perform public.notify_user(v_row.user_id, v_row.session_id, 'no_show',
      'ไม่ได้เช็คอินและยังค้างชำระ',
      'ก๊วนจบแล้วแต่ไม่มีการเช็คอินและยังไม่ได้ชำระ เครดิตของคุณลดลง 10 คะแนน', null);

    v_count := v_count + 1;
  end loop;

  return jsonb_build_object('noShows', v_count);
end;
$$;

revoke execute on function public.mark_no_shows() from public, authenticated;
grant execute on function public.mark_no_shows() to service_role;
```

```ts
export async function setCheckInAction(
  participantId: string,
  present: boolean,
): Promise<PayLaterResult> {
  const user = await getCurrentUser();
  if (!user) return { ok: false, error: reasonLabel.not_authenticated };

  const supabase = await createClient();
  const { data, error } = await supabase.rpc('set_check_in', {
    p_participant_id: participantId,
    p_present: present,
  });

  if (error) {
    console.error('[setCheckInAction] set_check_in failed', error);
    return { ok: false, error: t.common.unexpectedError };
  }

  const result = data as { ok?: boolean; reason?: string } | null;
  if (!result?.ok) return { ok: false, error: describe(result?.reason) };

  revalidatePath('/organizer', 'layout');
  return { ok: true };
}
```

```tsx
'use client';

import { useState, useTransition } from 'react';
import { setCheckInAction } from '@/lib/actions/participation';
import { checkInWindow } from '@/lib/domain/credit';
import { Button } from '@/components/ui/primitives';

type Props = {
  participantId: string;
  checkedInAt: string | null;
  startsAt: string;
  endsAt: string;
};

export function CheckInControl({ participantId, checkedInAt, startsAt, endsAt }: Props) {
  const [error, setError] = useState<string | null>(null);
  const [pending, startTransition] = useTransition();

  const window = checkInWindow(new Date(startsAt), new Date(endsAt));
  const open = window.isOpenAt(new Date());
  const present = Boolean(checkedInAt);

  // Disabled with the reason showing, never absent: the organizer should know
  // the control exists and why it cannot be used yet.
  if (!open) {
    return (
      <div className="flex flex-col items-end gap-1 text-right">
        <Button variant="secondary" size="sm" disabled>
          {present ? 'มาแล้ว' : 'เช็คอิน'}
        </Button>
        <p className="text-xs text-ink-500">
          {new Date() < window.opensAt ? 'ยังไม่ถึงเวลาเช็คอิน' : 'ปิดรับเช็คอินแล้ว'}
        </p>
      </div>
    );
  }

  return (
    <div className="flex flex-col items-end gap-1 text-right">
      <Button
        variant={present ? 'primary' : 'secondary'}
        size="sm"
        disabled={pending}
        onClick={() => {
          setError(null);
          startTransition(async () => {
            const result = await setCheckInAction(participantId, !present);
            if (!result.ok) setError(result.error);
          });
        }}
      >
        {present ? 'มาแล้ว' : 'เช็คอิน'}
      </Button>
      {error ? <p className="text-xs text-clay-700">{error}</p> : null}
    </div>
  );
}
```

### Risks and decisions

- **The ordering in Task 4 is the ticket.** Everything else here is additive.
  If `mark_no_shows()` is ever moved into the `Promise.all` for tidiness, the
  test in Task 7 that charges nobody for a `booking_failed` session still
  passes — it tests the SQL guard, not the ordering. The comment in
  `lifecycle.ts` is what protects the second guard; keep it.
- **−10 is proposed, not derived.** It sits beside LSN-0019's −5/day as a named
  constant with a parity check. If real groups say a single no-show should not
  cost two days of lateness, it is one line and one grep.
- **The window is duplicated in SQL.** Same defence-in-depth as the pay-later
  threshold, and the same obligation: change both.
- **A guest has no credit.** `mark_no_shows()` filters `user_id is not null`
  already, so LSN-0022 will not need to revisit it.

- The disabled state renders server-side and was read from the live page:
  `disabled: true`, reason "ยังไม่ถึงเวลาเช็คอิน" on every row.
- 7 pgTAP assertions cover the closed window, the authorization check, the
  charge, its idempotency, and the cancelled-session guard. 28 across three
  files; `npm run db:reset` applies all eleven migrations from scratch.

**One thing the plan got wrong, caught by Postgres.** The plan said to
`create or replace` `list_chaseable_participants()` with one column added. That
is invalid: a TABLE-returning function's row type cannot change under `create or
replace` (42P13). It has to be dropped first — and the drop silently takes the
`service_role` grant with it, which would have left the sweep unable to list
anybody. Both are now in the migration with a comment saying why.

**The two charges stack.** A player who neither showed up nor paid takes −10 and
−5 in the same sweep. Nobody decided that explicitly; it falls out of the two
rules being independent. It is defensible — those are two different failures —
and settling late still returns +10, so a four-day no-show who pays ends at −5
net. Flagged here rather than silently kept, because the ticket's open question
about the size of −10 should be answered knowing they add up.

**Still needs a human.** Nobody has clicked the enabled control. The page does
not hydrate in this environment — `hydrated: false`, and the pre-existing
"คัดลอกลิงก์" button does nothing either — so this is the harness, not the
change, and it was falsified rather than assumed this time. The window logic

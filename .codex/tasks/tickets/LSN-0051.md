# 🟢 LSN-0051 — CI รันเทสให้ทุก push และทุก PR

**Type:** Feature · **Phase:** 11 · **Status:** Done
**Source:** ของค้างจาก LSN-0047 และ LSN-0049

## ปัญหา

repo มี workflow เดียวคือ `sweep.yml` ซึ่งเป็นปุ่มกดเอง **ไม่มีอะไรรันเทสเลย**

วันที่ 19–20 ก.ย. เจอบั๊กสี่ตัวบนเบราว์เซอร์ที่เทส 400 กว่าข้อมองไม่เห็น
(LSN-0044 · LSN-0045) ทุกตัวแก้แล้วและมีตัวเฝ้าแล้ว แต่ตัวเฝ้าจะมีความหมาย
ก็ต่อเมื่อมีเครื่องรันให้ทุกครั้ง ไม่ใช่รอให้คนนึกได้

## Scope

- `.github/workflows/ci.yml` — สองงาน: `verify` และ `integration`
- `.github/workflows/grants-drift.yml` — ตรวจสิทธิ์สองฝั่ง รายสัปดาห์ + กดเองได้
- `scripts/write-ci-env.mjs` — สร้าง `.env.local` จาก `supabase status`

## Decisions

### แยกเป็นสองงาน ไม่ใช่งานเดียวยาว ๆ

`verify` (lint · typecheck · vitest) ไม่ต้องพึ่งอะไรเลย จบในนาทีเดียว
ส่วน `integration` ต้องดึงอิมเมจ Docker ของ Supabase กับเบราว์เซอร์ของ Playwright

แยกกันเพื่อให้ความผิดพลาดที่พบบ่อยที่สุดแดงภายในนาทีแรก แทนที่จะต้องรอ Docker

### `grants-drift` แยกออกมาและไม่รันทุก PR

งานนั้นต้องคุยกับ **production** จึงต้องใช้ความลับ ถ้าผูกไว้กับ PR แปลว่า PR
จากใครก็ได้จะได้สิทธิ์แตะฐานข้อมูลจริง รายสัปดาห์พอ เพราะสิทธิ์เบี่ยงตอนมี
migration ใหม่ ไม่ได้เบี่ยงเองรายชั่วโมง

**ข้ามเงียบ ๆ ถ้ายังไม่ได้ตั้งความลับ** ไม่แดง — จะได้ไม่มีเสียงเตือนหลอกทุกสัปดาห์
จนคนเลิกสนใจ ซึ่งแย่กว่าไม่มี CI

### `.env.local` สร้างจาก `supabase status` ไม่ใช่ฝังค่าไว้

คีย์ของ Supabase ในเครื่องเป็นค่าคงที่สำหรับ dev ไม่ใช่ความลับ แต่ถ้าฝังไว้ใน
workflow แล้ววันหนึ่ง CLI เปลี่ยนค่า จะต้องตามแก้ทั้งที่ไม่มีใครรู้ว่าต้องแก้

### สคริปต์แยกไฟล์ ไม่ใช่ `node -e` ในไฟล์ YAML

ตอนแรกเขียนเป็น `node -e '...'` ยาว ๆ ในขั้นตอนของ workflow แล้วเผลอใส่คอมเมนต์
ด้วย `#` ซึ่งเป็นคอมเมนต์ของเชลล์ ไม่ใช่ของ JavaScript — โค้ดพังแน่นอนแต่จะรู้
ก็ต่อเมื่อ CI รันแล้วเท่านั้น

ย้ายเป็นไฟล์จริงจึงรันทดสอบในเครื่องได้ก่อนส่ง และพบบั๊กที่สองทันที (ข้างล่าง)

## Review Notes — 20 ก.ย. 2569

### บั๊กที่จับได้ก่อนขึ้น เพราะทดสอบสคริปต์ในเครื่อง

`supabase status -o json` **ไม่ได้พิมพ์ JSON ล้วน** มันมีบรรทัดนำหน้าว่า

```
Stopped services: [supabase_imgproxy_longsanam supabase_analytics_longsanam …]
```

`JSON.parse` ทั้งก้อนจึงพังทันที ต้องตัดตั้งแต่ปีกกาแรก

ถ้าปล่อยเป็น `node -e` ใน YAML ตามที่เขียนตอนแรก บั๊กนี้จะโผล่ตอน CI รันจริง
และคนอ่าน log จะเห็นแค่ `SyntaxError` โดยไม่รู้ว่ามาจากบรรทัดที่ CLI พิมพ์แถมมา

### ของที่ยังไม่ได้ทำ

- **ยังไม่ได้ตั้ง required check** บน branch `main` — GitHub Free กับ repo ส่วนตัว
  ตั้ง branch protection ไม่ได้ ต้องอัปเป็น Pro หรือเปลี่ยน repo เป็น public
  ตอนนี้ CI จึงเป็นสัญญาณ ไม่ใช่ประตู
- `grants-drift` ต้องตั้งความลับสามตัวก่อนถึงจะทำงาน:
  `SUPABASE_ACCESS_TOKEN` · `SUPABASE_DB_PASSWORD` · `SUPABASE_PROJECT_REF`
- E2E ยังเดินเส้นทางเดียว (ทัวร์นาเมนต์) ฝั่งก๊วนยังไม่ครอบ — ค้างจาก LSN-0047

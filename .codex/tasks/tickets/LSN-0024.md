# 🟢 LSN-0024 — รายการเก็บเงินเพิ่มหลังจบก๊วน

**Type:** Feature · **Phase:** 9 · **Status:** Backlog
**Spec:** `.codex/specs/extra-charges.md`
**Depends on:** LSN-0021 (ตัวหารและกติกาห้ามแตะคนที่จ่ายแล้ว), LSN-0022 (ผู้เล่นรับเชิญ — **ยังอยู่ใน review**)

## Goal

ผู้จัดก๊วนสร้างรายการค่าใช้จ่ายเพิ่มเติมหลังเล่นจบได้หลายบรรทัด เช่น ค่าลูกแบดที่ซื้อระหว่างเล่น
หรือค่าไม้ที่บางคนยืม แล้วระบบเรียกเก็บให้ แทนที่ผู้จัดจะต้องพิมพ์ทวงในกลุ่ม LINE เอง

## Context

LSN-0021 หารค่าใช้จ่ายตามคนที่มาจริงได้แล้ว แต่เก็บค่าลูกไว้ในช่องเดียวชื่อ
`sessions.shuttle_cost_thb` ซึ่งตั้งชื่อไม่ได้ แยกประเภทไม่ได้ และหารเท่ากันทุกคนเสมอ
ทั้งที่ค่าไม้ควรลงเฉพาะคนที่ยืม

ตั๋วนี้เพิ่มรายการค่าใช้จ่ายแบบหลายบรรทัด โดย **ไม่แตะ** `shuttle_cost_thb` และ
**ไม่แตะ** ยอดที่แต่ละคนตกลงจ่ายไปแล้ว

## Scope

- ตาราง `session_charges` (บรรทัดค่าใช้จ่าย) และ `session_charge_shares` (ส่วนแบ่งรายคน)
- RPC สร้าง ส่งเรียกเก็บ และลบรายการ เฉพาะผู้จัดก๊วน
- ส่วนแบ่งคำนวณตอนสร้างและเก็บเป็นแถว ไม่คำนวณสดทีหลัง
- แต่ละบรรทัดเลือก split ของตัวเอง: `all` (หารคนที่นับในตัวหารตามกติกา LSN-0021) หรือ `named` (เฉพาะคนที่เลือก)
- UI ฝั่งผู้จัดสำหรับสร้าง ดูตัวอย่างว่าใครโดนเท่าไร ส่งเรียกเก็บ และลบรายการ
- ผู้เล่นเห็นยอดที่ตัวเองถูกเรียกเก็บ และจ่ายผ่านช่องทางเดิม

## Non-goals

- ไม่ทำระบบสต็อกอุปกรณ์ ไม่ผูกกับสินค้าของสนาม
- ไม่ให้ผู้เล่นสร้างรายการเอง
- ไม่ทำการคืนเงินรายการเพิ่มเติม — พิมพ์ผิดให้ลบบรรทัดแล้วสร้างใหม่
- ไม่ย้าย `shuttle_cost_thb` เข้าตารางใหม่ในรอบนี้ (บันทึกเป็นหนี้ทางเทคนิค)
- ไม่แตะ `budget_per_person_thb` ซึ่งเป็นยอดที่ผู้เล่นตกลงตอนกดเข้าร่วม

## Decisions from the spec

ห้าข้อนี้ตัดสินไว้ใน spec แล้ว พร้อมเหตุผล — ถ้าจะเปลี่ยนต้องเปลี่ยนที่ spec ก่อน

1. **split เลือกได้ต่อบรรทัด** (`all` / `named`) เพราะค่าไม้ไม่ควรหารทั้งก๊วน
   นี่คือเหตุผลที่ฟีเจอร์นี้ไม่ใช่แค่เพิ่มช่องใน `settle_session_costs` ซึ่ง `split_mode`
   ของมันเป็นของทั้งก๊วน ไม่ใช่ของรายบรรทัด
2. **สร้างได้เฉพาะก๊วน `booked` หรือ `completed`** — allowlist ไม่ใช่ denylist
   ด้วยเหตุผลเดียวกับบั๊กที่เคยเจอใน LSN-0020: denylist ปล่อยให้ `open` / `draft` /
   `ready_to_book` หลุดเข้ามา ซึ่งเป็นก๊วนที่ยังไม่ได้สนามด้วยซ้ำ
3. **เรียกเก็บจากคนที่จ่ายแล้วได้ แต่เป็นหนี้ก้อนใหม่** กติกาของ LSN-0021 ห้ามเขียนทับ
   ยอดที่ตกลงไปแล้ว ไม่ได้ห้ามขอเงินเพิ่ม ดังนั้นรายการเพิ่มเติมต้องสร้าง `payments`
   แถวใหม่ ห้ามแตะ `amount_due_thb` หรือ `payments` แถวเดิม
4. **ผู้เล่นรับเชิญ** บันทึกส่วนแบ่งให้เห็นบนหน้าจอ แต่ไม่สร้าง `payments`
   ไม่เข้าคิวทวง ไม่แตะเครดิต — ตรงกับที่ LSN-0022 วางไว้
5. **ไม่หักเครดิต** เพราะผู้จัดพิมพ์ชื่อและยอดเอง ถ้าหักได้จะกลายเป็นช่องให้สร้างรายการ
   ปลอมลงชื่อคนที่ไม่ถูกกัน แล้วทำคะแนนเขาร่วง — พังระบบเครดิตที่ LSN-0019 สร้างไว้
   เป็นเกณฑ์ให้สิทธิ์จ่ายทีหลัง

## Open Questions — ตัดสินครบแล้ว 11 ก.ย.

### 1. ชื่อรายการ → พิมพ์เอง แต่มีชิปกดเติมเร็ว ไม่มีตาราง

เก็บใน DB เป็น free text เหมือนเดิม แต่ UI มีชิปให้กดเติมช่องข้อความ ตามกีฬาของก๊วนนั้น
เช่นแบดมินตันขึ้น "ค่าลูกแบด · ค่าไม้ · ค่าคอร์ตเพิ่ม" ฟุตบอลขึ้น "ค่าเสื้อ · ค่าน้ำ"

ชิปเป็น `Record<sportSlug, string[]>` ฮาร์ดโค้ดใน `src/i18n/th.ts`
**ไม่มีตารางใหม่ ไม่มี migration ไม่มี API** ค่าที่บันทึกยังเป็นข้อความที่ผู้จัดยืนยัน

เหตุผล: non-goal ของตั๋วนี้เขียนไว้เองว่า "ไม่ทำระบบสต็อกอุปกรณ์ ไม่ผูกกับสินค้าของสนาม"
ตารางรายการสำเร็จรูปคือก้าวแรกของระบบสต็อก แล้วจะตามมาด้วยคำถามว่าใครแก้ได้
ลบแล้วของเก่าเป็นอะไร แปลภาษายังไง ชิปฮาร์ดโค้ดให้ผลทาง UX เกือบเท่ากันโดยไม่เปิดประตูนั้น
และเปลี่ยนทีหลังได้ด้วยการแก้ไฟล์เดียว มี `sports` อยู่ 6 แถวรวม `custom` จึงครอบคลุมครบ

### 2. เพดานยอด → สองชั้น คนละหน้าที่กัน

**ชั้นฐานข้อมูล:** `check (amount_thb > 0 and amount_thb <= 100000)`

- `> 0` ไม่ใช่ `>= 0` — รายการ ฿0 ไม่มีความหมาย และจะสร้าง payment ฿0
  กับแจ้งเตือนคนที่ไม่ได้ติดเงิน
- `<= 100000` เป็นเพดานกันพิมพ์ผิด ไม่ใช่เพดานเชิงธุรกิจ ฿100,000 สำหรับรายการเดียว
  ในก๊วนสมัครเล่นเป็นไปไม่ได้ มันจับ "เผลอใส่ศูนย์เกิน" โดยไม่เคยขวางยอดจริง

**ชั้น UI:** ยอดเกิน ฿2,000 ต้องกดยืนยันอีกครั้ง โดยกล่องยืนยัน**แสดงยอดต่อคน**
("฿5,000 หาร 8 คน = คนละ ฿625 ยืนยันไหม") ตรงนี้คือที่ที่พิมพ์ผิดถูกจับจริง
เพราะคนมองเลขต่อคนแล้วรู้ทันที ส่วน check ใน DB เป็นตาข่ายชั้นสุดท้ายเผื่อมีใครเรียก RPC ตรง

**ความไม่สม่ำเสมอที่ตั้งใจ:** ตรวจแล้วว่าทั้งสคีมาไม่มีคอลัมน์เงินไหนมีเพดานเลย
มีแต่ `>= 0` การใส่เพดานเฉพาะตารางนี้จึงต่างจากที่อื่น — แต่ตารางนี้ต่างจริง
เพราะ**ผู้จัดพิมพ์เลขเองแล้วมันกลายเป็นหนี้ของคนอื่นทันที** ต่างจาก
`budget_per_person_thb` ที่ผู้เล่นเห็นและกดยอมรับก่อนเข้าร่วม

### 3. แจ้งเตือน → มีขั้นตอน "ส่งเรียกเก็บ" แยกต่างหาก

สร้างรายการแล้ว **ยังไม่แจ้งใคร และยังไม่มีหนี้เกิดขึ้น** ผู้จัดสร้างได้หลายบรรทัด
ดูว่าใครโดนเท่าไร แล้วค่อยกดส่งครั้งเดียว

**ผลต่อสคีมาและลำดับการทำงาน:**

- `session_charges.notified_at timestamptz` — null แปลว่ายังเป็นฉบับร่าง
- `session_charge_shares` สร้างตั้งแต่ตอนสร้างรายการ เพื่อให้ผู้จัด**เห็นล่วงหน้า**
  ว่าใครโดนเท่าไรก่อนตัดสินใจส่ง
- **`payments` สร้างตอนกดส่งเท่านั้น** ไม่ใช่ตอนสร้างรายการ
  เพราะหนี้ไม่ควรโผล่ในหน้าจอผู้เล่นก่อนที่ผู้จัดจะตั้งใจเรียกเก็บ
- แจ้งเตือน **หนึ่งครั้งต่อคน** สรุปยอดรวมของทุกบรรทัดที่ส่งรอบนั้น ไม่ใช่ต่อบรรทัด
  (ตรวจแล้วว่าระบบยังไม่มีกลไกรวมแจ้งเตือนเลย `notify_user` มี 9 call site แต่ละที่ยิงทีละแถว
  ตัวนี้จะเป็นตัวแรกที่รวม)

**สิ่งที่ได้มาฟรีและมีค่ากว่าที่คิด:** รายการที่พิมพ์ผิดลบทิ้งได้เงียบ ๆ ก่อนมีใครรู้
กล่องยืนยันในข้อ 2 จึงไม่ใช่ด่านสุดท้าย ถ้ามันหลุดมายังมีจังหวะให้แก้

**ต้นทุน:** หนึ่งคอลัมน์ หนึ่ง RPC หนึ่งปุ่ม ถูกกว่าการต้องอธิบายให้ผู้เล่นแปดคนฟัง
ว่าทำไมมีหนี้โผล่มาแล้วหายไป

```sql
create or replace function public.session_denominator(p_session_id uuid)
returns setof public.session_participants
language sql
stable
set search_path = public, pg_temp
as $$
  select sp.*
  from public.session_participants sp
  where sp.session_id = p_session_id
    and sp.status in ('paid_confirmed', 'joined_pay_later', 'payment_overdue')
    and (
      not exists (
        select 1 from public.session_participants x
        where x.session_id = p_session_id and x.checked_in_at is not null
      )
      or sp.checked_in_at is not null
    );
$$;

revoke execute on function public.session_denominator(uuid) from public;
```

```sql
create or replace function public.create_session_charge(
  p_session_id      uuid,
  p_label           text,
  p_amount_thb      integer,
  p_split_mode      public.charge_split_mode,
  p_participant_ids uuid[] default null
) returns jsonb
language plpgsql security definer
set search_path = public, pg_temp
as $$
declare
  v_session public.sessions%rowtype;
  v_charge  uuid;
  v_ids     uuid[];
  v_n       integer;
  v_share   integer;
begin
  select * into v_session from public.sessions where id = p_session_id;
  if v_session.id is null then
    return jsonb_build_object('ok', false, 'reason', 'session_not_found');
  end if;
  if not public.is_session_organizer(p_session_id) then
    return jsonb_build_object('ok', false, 'reason', 'not_organizer');
  end if;

  -- allowlist ไม่ใช่ denylist ด้วยเหตุผลเดียวกับบั๊ก LSN-0020:
  -- denylist ปล่อย draft / open / ready_to_book เข้ามา ซึ่งยังไม่ได้สนามด้วยซ้ำ
  if v_session.status not in ('booked', 'completed') then
    return jsonb_build_object('ok', false, 'reason', 'session_not_played');
  end if;

  if p_split_mode = 'all' then
    select array_agg(d.id) into v_ids from public.session_denominator(p_session_id) d;
  else
    select array_agg(sp.id) into v_ids
    from public.session_participants sp
    where sp.session_id = p_session_id
      and sp.id = any(coalesce(p_participant_ids, '{}'::uuid[]));
  end if;

  v_n := coalesce(array_length(v_ids, 1), 0);
  if v_n = 0 then
    return jsonb_build_object('ok', false, 'reason', 'no_participants');
  end if;

  -- ปัดขึ้น ผู้จัดรับส่วนต่าง — กติกาเดียวกับ LSN-0021
  v_share := ceil(p_amount_thb::numeric / v_n);

  insert into public.session_charges (session_id, label, amount_thb, split_mode, created_by)
  values (p_session_id, btrim(p_label), p_amount_thb, p_split_mode, auth.uid())
  returning id into v_charge;

  insert into public.session_charge_shares (charge_id, participant_id, amount_thb)
  select v_charge, unnest(v_ids), v_share;

  perform public.app_log(auth.uid(), 'session_charge', v_charge, p_session_id,
    'charge.created', null, p_amount_thb::text,
    jsonb_build_object('label', btrim(p_label), 'splitMode', p_split_mode,
                       'people', v_n, 'perHeadThb', v_share));

  return jsonb_build_object('ok', true, 'chargeId', v_charge,
    'people', v_n, 'perHeadThb', v_share);
end;
$$;

revoke execute on function public.create_session_charge(uuid, text, integer, public.charge_split_mode, uuid[]) from public;
grant execute on function public.create_session_charge(uuid, text, integer, public.charge_split_mode, uuid[]) to authenticated, service_role;
```

```sql
create or replace function public.send_session_charges(p_session_id uuid)
returns jsonb
language plpgsql security definer
set search_path = public, pg_temp
as $$
declare
  v_row     record;
  v_payment uuid;
  v_charges integer := 0;
  v_people  integer := 0;
begin
  if not public.is_session_organizer(p_session_id) then
    return jsonb_build_object('ok', false, 'reason', 'not_organizer');
  end if;

  -- หนี้เกิดตรงนี้ ไม่ใช่ตอนสร้างรายการ
  for v_row in
    select s.id as share_id, s.amount_thb, sp.id as participant_id,
           sp.user_id, c.id as charge_id
    from public.session_charge_shares s
    join public.session_charges c on c.id = s.charge_id
    join public.session_participants sp on sp.id = s.participant_id
    where c.session_id = p_session_id
      and c.notified_at is null and c.voided_at is null
      and s.payment_id is null
      and sp.user_id is not null   -- ผู้เล่นรับเชิญ: มีส่วนแบ่ง ไม่มีหนี้
  loop
    insert into public.payments (session_id, participant_id, user_id, amount_thb,
                                 status, provider, idempotency_key)
    values (p_session_id, v_row.participant_id, v_row.user_id, v_row.amount_thb,
            'pending', 'mock', 'charge:' || v_row.share_id::text)
    returning id into v_payment;

    update public.session_charge_shares set payment_id = v_payment
    where id = v_row.share_id;
  end loop;

  -- แจ้ง "หนึ่งครั้งต่อคน" ไม่ใช่ต่อบรรทัด — call site แรกของระบบที่รวมแจ้งเตือน
  -- notify_user อีก 9 ที่ยิงทีละแถว ที่นี่ยิงหลังรวมยอดแล้ว
  for v_row in
    select sp.user_id, sum(s.amount_thb)::integer as total_thb, count(*)::integer as lines
    from public.session_charge_shares s
    join public.session_charges c on c.id = s.charge_id
    join public.session_participants sp on sp.id = s.participant_id
    where c.session_id = p_session_id
      and c.notified_at is null and c.voided_at is null
      and sp.user_id is not null
    group by sp.user_id
  loop
    perform public.notify_user(v_row.user_id, p_session_id, 'extra_charge',
      'มีรายการเก็บเงินเพิ่ม',
      'ก๊วนนี้มีรายการเพิ่มเติม ' || v_row.lines || ' รายการ รวม ฿' || v_row.total_thb,
      '/s/' || (select public_code from public.sessions where id = p_session_id) || '/receipt');
    v_people := v_people + 1;
  end loop;

  update public.session_charges
  set notified_at = now()
  where session_id = p_session_id and notified_at is null and voided_at is null;
  get diagnostics v_charges = row_count;

  perform public.app_log(auth.uid(), 'session', p_session_id, p_session_id,
    'charge.sent', null, v_charges::text,
    jsonb_build_object('charges', v_charges, 'peopleNotified', v_people));

  return jsonb_build_object('ok', true, 'charges', v_charges, 'peopleNotified', v_people);
end;
$$;
```

```sql
create or replace function public.void_session_charge(p_charge_id uuid)
returns jsonb
language plpgsql security definer
set search_path = public, pg_temp
as $$
declare
  v_charge public.session_charges%rowtype;
  v_voided integer;
begin
  select * into v_charge from public.session_charges where id = p_charge_id;
  if v_charge.id is null then
    return jsonb_build_object('ok', false, 'reason', 'charge_not_found');
  end if;
  if not public.is_session_organizer(v_charge.session_id) then
    return jsonb_build_object('ok', false, 'reason', 'not_organizer');
  end if;
  if v_charge.voided_at is not null then
    return jsonb_build_object('ok', false, 'reason', 'already_voided');
  end if;

  -- expired ไม่ใช่ delete: หนี้ที่เคยมีอยู่จริงต้องอธิบายได้ทีหลัง
  update public.payments p set status = 'expired', updated_at = now()
  from public.session_charge_shares s
  where s.charge_id = p_charge_id and p.id = s.payment_id and p.status = 'pending';
  get diagnostics v_voided = row_count;

  update public.session_charges set voided_at = now() where id = p_charge_id;

  perform public.app_log(auth.uid(), 'session_charge', p_charge_id, v_charge.session_id,
    'charge.voided', v_charge.amount_thb::text, null,
    jsonb_build_object('paymentsExpired', v_voided,
                       'wasDraft', v_charge.notified_at is null));

  return jsonb_build_object('ok', true, 'paymentsExpired', v_voided);
end;
$$;
```

UI ต้องบอกล่วงหน้าว่า “฿5,000 หาร 8 คน = คนละ ฿625” ก่อนกดสร้าง ซึ่งเป็นเลข

```ts
/** ปัดขึ้น ผู้จัดรับส่วนต่าง — เลขเดียวกับที่ create_session_charge() คำนวณ */
export function chargeShareThb(amountThb: number, people: number): number {
  if (people <= 0) return 0;
  return Math.ceil(amountThb / people);
}

/** ยอดที่เกินจากการปัด ซึ่งตกเป็นของผู้จัด */
export function chargeOverageThb(amountThb: number, people: number): number {
  if (people <= 0) return 0;
  return chargeShareThb(amountThb, people) * people - amountThb;
}
```

`idempotency_key = 'charge:' || share_id` กันการสร้าง payment ซ้ำของ share เดิมได้

(ซึ่งโค้ดข้างบนทำแล้ว) และบันทึกไว้ว่าเป็นการกันระดับ transaction ไม่ใช่ระดับ unique

จะกรอกค่าลูกตรงไหน นั่นคือสัญญาณให้ย้าย — เป็นตั๋วคนละใบ

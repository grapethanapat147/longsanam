# 🟢 LSN-0041 — เลือกวันเป็น พ.ศ.

**Type:** Feature · **Phase:** 10 · **Status:** Done
**Source:** เกรพขอโดยตรง 18 ก.ย. 2569
**Depends on:** LSN-0040 — merge แล้ว

## Goal

ให้ช่องเลือกวันในฟอร์มสร้างทัวร์นาเมนต์แสดงปีเป็น **พ.ศ.**

## Context

**ฝั่งแสดงผลเป็น พ.ศ. อยู่แล้ว** — `LOCALE = 'th-TH'` ทำให้ `Intl.DateTimeFormat`
ใช้ปฏิทินพุทธเป็นค่าเริ่มต้น ตรวจแล้วได้ `วันอาทิตย์ที่ 15 พฤศจิกายน 2569`

ที่ยังเป็น ค.ศ. คือ **ตัวเลือกวันของเบราว์เซอร์** (`<input type="date">`)
ซึ่งใช้ปฏิทินของระบบปฏิบัติการ ไม่ฟังค่า locale ของเว็บ

## Decisions

### เลือกสามช่อง วัน / เดือน / ปี แทนปฏิทินป๊อปอัป

เขียนปฏิทินเองแปลว่าต้องทำ ตารางเดือน · ปุ่มเลื่อนเดือน · การกดด้วยคีย์บอร์ด ·
กับดักโฟกัส · ปิดเมื่อคลิกนอก · การแตะบนมือถือ — ประมาณ 300–400 บรรทัดที่ต้องดูแลเอง
และเป็นพื้นผิวที่พังเงียบได้หลายทาง

สามช่องเลือกให้ผลเดียวกันคือ **เห็นปีเป็น พ.ศ.** ด้วยโค้ดที่น้อยกว่ามาก
และเป็นแพตเทิร์นที่ฟอร์มราชการและเว็บไทยใช้กันจนคนคุ้นอยู่แล้ว
บนมือถือยังได้วงล้อเลือกของระบบซึ่งใช้ง่ายกว่าปฏิทินที่เขียนเอง

**ข้อแลกเปลี่ยนที่รู้ตัว:** ปฏิทินทำให้เห็นว่าวันไหนเป็นเสาร์อาทิตย์โดยไม่ต้องคิด
ซึ่งสำคัญกับงานแข่งที่มักจัดวันหยุด จึงชดเชยด้วย **บรรทัดบอกวันในสัปดาห์
ทันทีที่เลือกครบ** และบรรทัดทวนใต้ฟอร์มที่มีอยู่แล้วจาก LSN-0040

### เก็บค่าเป็น ค.ศ. เหมือนเดิม แปลงเฉพาะตอนแสดง

ข้างในยังเป็น `yyyy-mm-dd` แบบ ค.ศ. ทุกจุด ตั้งแต่ state จนถึงฐานข้อมูล
**พ.ศ. อยู่แค่ชั้นที่ผู้ใช้เห็น** ถ้าเก็บเป็น พ.ศ. ปนเข้าไปในระบบเมื่อไร
จะมีวันที่ใครสักคนลืมลบ 543 แล้วข้อมูลเพี้ยนแบบหาสาเหตุยาก

## Scope

- Component ใหม่ `ThaiDateField` — วัน / เดือน(ชื่อไทย) / ปี(พ.ศ.)
- ใช้กับ **วันแข่ง** และ **รับสมัครถึงวันไหน** ในฟอร์มสร้างทัวร์นาเมนต์
- บอกวันในสัปดาห์ทันทีที่เลือกครบ
- ปรับวันอัตโนมัติเมื่อเปลี่ยนเดือนแล้ววันเกิน (31 ก.พ. ต้องไม่เกิดขึ้น)

## Non-goals

- ไม่แตะฟอร์มสร้างนัด (`/organizer/new`) — คนละฟอร์ม ถ้าจะทำควรเป็นตั๋วแยก
- ไม่เปลี่ยนวิธีเก็บข้อมูล ไม่มี migration
- ไม่ทำปฏิทินป๊อปอัป

### สองครั้งที่ผมวินิจฉัยผิดระหว่างทดสอบ และไม่ใช่บั๊กของโค้ด

**1. "หน้าไม่ hydrate"** — ผมเช็คว่ามี `__reactFiber$` บน DOM element ไหม แล้วไม่เจอ
จึงสรุปว่า client bundle ไม่ทำงาน **ผิด** — React 19 ไม่ได้แปะคีย์นั้นแบบที่ผมคาด
พิสูจน์ด้วยการพิมพ์จริงในช่องชื่อรายการแล้วปุ่มสร้างปลดล็อก แปลว่า hydrate ปกติ

**2. "ยัดค่า select แล้ว React ไม่รับรู้"** — ที่จริงต้องยิง **ทั้ง `input` และ `change`**
และต้อง re-query element ใหม่หลังทุกครั้งที่ re-render ยิงแค่ `change` อย่างเดียวไม่พอ
พอทำถูกแล้วทุกอย่างตอบสนองปกติ

บันทึกไว้เพราะเสียเวลาไปหลายรอบกับเรื่องนี้ และจะเจอซ้ำแน่ถ้าไม่จด

# 🟢 LSN-0033 — แสดงเฉพาะแบดมินตัน ปิดกีฬาอื่นไว้ก่อน

**Type:** Feature · **Phase:** 10 · **Status:** In Progress
**Source:** `docs/product-concept.md` หัวข้อ "ทำไมแบดมินตันอย่างเดียว"

## Goal

ให้ทุกหน้าจอที่ให้ผู้ใช้เลือกกีฬา **เหลือแบดมินตันอย่างเดียว** และปิดอีกห้ากีฬาไว้
โดยเปิดกลับได้ง่ายเมื่อถึงเวลา

## Context

ระบบมีกีฬาอยู่หกตัวจาก `20260901000700_reference_data.sql` — แบดมินตัน · ฟุตบอล ·
เทนนิส · บาสเกตบอล · พิคเคิลบอล · กีฬาอื่น ๆ ทั้งที่ `docs/product-concept.md`
ตัดสินไปแล้วว่าโปรดักต์นี้เป็นของแบดมินตันอย่างเดียว และเขียนเหตุผลไว้ชัดว่า
*"ทุกกีฬา แปลว่าไม่ได้ออกแบบให้ใครโดยเฉพาะ"*

**ของดีที่มีอยู่แล้ว** — ตาราง `sports` มีคอลัมน์ `is_active` และ `loadSports()`
(`src/lib/queries.ts:234`) ก็กรอง `.eq('is_active', true)` อยู่แล้ว จึงไม่ต้องสร้างกลไกใหม่
แค่ปิดสวิตช์ที่มีอยู่

**และ upsert ของ `reference_data` ไม่ได้เซ็ต `is_active`** (มันเซ็ตแค่ slug, name, emoji,
default_players, sort_order) การปิดในภายหลังจึงไม่ถูกเขียนทับถ้ามีใครรัน migration นั้นซ้ำ

### รอยรั่วที่ต้องอุด

`src/app/app/groups/page.tsx:21` **ไม่ได้ใช้ `loadSports()`** แต่ยิง query เองและ
**ไม่กรอง `is_active`**

```ts
const { data: sports } = await supabase.from('sports').select('id, name_th').order('name_th');
```

ถ้าปิดแค่ในฐานข้อมูล หน้าสร้างก๊วนจะยังโชว์ครบหกกีฬาอยู่ดี

## Scope

- Migration ปิดกีฬาอื่น: `update public.sports set is_active = false where slug <> 'badminton'`
- แก้ `src/app/app/groups/page.tsx` ให้ใช้ `loadSports()` แทน query ของตัวเอง
  เพื่อให้เหลือ **ต้นฉบับเดียว** ของคำว่า "กีฬาที่เปิดใช้" ตามแนวเดียวกับ
  `session_denominator()` และ `confirmed_matches()`
- ตรวจหน้าจอที่เหลือให้แสดงผลดีเมื่อมีกีฬาเดียว ไม่ใช่แค่ "ไม่พัง"
  - `CreateSessionWizard` — ปุ่มเลือกกีฬาเหลือตัวเดียว
  - `/discover` — ตัวกรองกีฬาเหลือตัวเดียว
  - `/venue/[venueId]/courts` — เจ้าของสนามติดแท็กคอร์ตได้เฉพาะแบด

## Non-goals

- **ไม่ลบข้อมูลกีฬาอื่นออกจากฐานข้อมูล** — ปิดสวิตช์เท่านั้น เปิดกลับได้ด้วย
  `update ... set is_active = true` คำสั่งเดียว
- ไม่ลบแถวใน `court_sports` ที่ผูกคอร์ตกับกีฬาอื่นไว้แล้ว — ปล่อยไว้เฉย ๆ ไม่มีผล
- ไม่แตะนัดหรือก๊วนที่มีอยู่แล้ว ถึงจะเป็นกีฬาอื่นก็ยังอยู่ได้ตามเดิม

## Decisions

### ปิดที่ฐานข้อมูล ไม่ใช่ hardcode ในโค้ด

`is_active` มีอยู่เพื่อการนี้อยู่แล้ว การ hardcode `slug === 'badminton'` ในโค้ด
จะทำให้เปิดกลับต้องแก้โค้ดและ deploy ใหม่ ส่วนการปิดที่ข้อมูลเปิดกลับได้ด้วย SQL บรรทัดเดียว

**ข้อแลกเปลี่ยนที่ต้องรู้:** migration นี้จะยังไม่มีผลบน production จนกว่าจะรัน
`db push` ซึ่งตอนนี้ค้างอยู่ 13 ตัว ตัวนี้จะเป็นตัวที่ 14 — บน production
กีฬาอื่นจะยังโผล่อยู่จนกว่าจะ push

### ซ่อน ไม่ใช่ทำเป็นสีเทา

คำขอเดิมคือ "ให้กีฬาอื่นเป็น disabled และโชว์เพียงแบด" — เลือกทางซ่อน เพราะปุ่มสีเทา
ที่กดไม่ได้คือการโฆษณาสิ่งที่ยังไม่มี ผู้ใช้จะถามว่าเมื่อไหร่จะเปิด ซึ่งเรายังตอบไม่ได้

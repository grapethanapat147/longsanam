# 🟢 LSN-0027 — เปลี่ยนคำ: ก๊วน → นัด

**Type:** Feature · **Phase:** 10 · **Status:** Backlog
**Spec:** `.codex/specs/tournaments.md` หัวข้อ Decisions ข้อ 2
**Depends on:** ไม่มี — **แต่ตั๋วนี้ต้อง merge ก่อน LSN-0026 เริ่ม**

## Goal

คำว่า **"ก๊วน"** ในแอปทุกวันนี้หมายถึง *การนัดเล่นหนึ่งครั้ง* เปลี่ยนเป็น **"นัด"**
เพื่อปล่อยคำว่า "ก๊วน" ให้ว่างสำหรับ *กลุ่มคน* ที่ LSN-0026 จะเพิ่มเข้ามา

## Context

`sessions` หนึ่งแถวคือการนัดเล่นหนึ่งครั้ง แต่ UI เรียกมันว่า "ก๊วน" ส่วน flow
ทัวร์นาเมนต์ใช้คำว่าก๊วนหมายถึงกลุ่มคนที่เล่นด้วยกันประจำ

**ตัวที่บังคับว่าต้องทำก่อน ไม่ใช่ทำทีหลัง:** เมนูใน nav ชื่อ **"ก๊วนของฉัน"**
ซึ่งวันนี้แปลว่า *นัดของฉัน* ทันทีที่ LSN-0026 เพิ่มก๊วนที่เป็นกลุ่มคน ป้ายเดียวนั้น
จะมีสองความหมายบนหน้าจอเดียวกัน ถ้าเปลี่ยนคำก่อน จะไม่มีช่วงที่ผู้ใช้เห็นสอง
ความหมายเลยแม้แต่วันเดียว

ภาษาไทยใช้ "ก๊วน" ได้ทั้งสองความหมายอยู่แล้ว การเลือกให้ก๊วน = กลุ่มคน คือการเลือก
ความหมายที่ตรงกับที่คนแบดใช้พูดถึงชุมชนตัวเอง ("อยู่ก๊วนนี้มาสองปีแล้ว")
ส่วน "นัด" ก็เป็นคำที่ใช้กันอยู่แล้ว ("นัดตีแบดวันพุธ")

## ส่วนที่พลาดง่ายที่สุด: ข้อความแจ้งเตือนอยู่ใน SQL

การแก้แค่ `src/` จะทำให้แจ้งเตือนยังใช้คำเก่า ผู้ใช้เห็นสองคำในแอปเดียวต่อไป
มี **5 จุด** อยู่ใน **3 ฟังก์ชันที่ยังทำงานจริง**:

| ฟังก์ชัน | นิยามล่าสุดอยู่ที่ | ข้อความ |
| --- | --- | --- |
| `promote_waitlist` | `20260901000200_functions.sql:1024` | "มีที่ว่างในก๊วนที่คุณรออยู่…" |
| `mark_no_shows` | `20260909000100_check_in.sql:136` | "ก๊วนจบแล้วแต่ไม่มีการเช็คอิน…" |
| `void_pay_later_on_session_end` | **`20260911000100_guest_participants.sql:432`** | "ก๊วนถูกยกเลิกและระบบไม่ได้จองสนามให้…" |

### ⚠️ กับดักของ `void_pay_later_on_session_end`

ฟังก์ชันนี้ถูก `create or replace` **สามครั้ง** ในสาม migration:
`20260905000100_pay_later_credit.sql:514` → `20260910000100_settlement.sql:240` →
`20260911000100_guest_participants.sql:432`

**ตัวที่มีผลจริงคือตัวสุดท้าย** ตรวจในฐานข้อมูลแล้วยืนยันว่าเป็นตัวของ LSN-0022
เพราะมี guard `if v_row.user_id is null then continue` อยู่ในลูป

**ถ้าใครคัดลอกจากไฟล์แรกหรือไฟล์กลางมาแก้คำ จะย้อน guard นั้นทิ้งโดยเงียบ ๆ**
guard นั้นคือสิ่งที่แก้ blocker ของ LSN-0022 ซึ่งทำให้**ก๊วนที่มีผู้เล่นรับเชิญค้างจ่าย
ยกเลิกไม่ได้เลย** เพราะ `notify_user(null, …)` ชน NOT NULL ของ `notifications.user_id`
แล้ว UPDATE ล้มทั้งคำสั่ง

→ ต้องคัดลอกจาก `20260911000100_guest_participants.sql` เท่านั้น และมีเทสยืนยัน

### ห้ามแก้ migration เก่า

การแก้ข้อความใน migration ที่ apply ไปแล้ว **ไม่เปลี่ยนฟังก์ชันที่ทำงานอยู่จริง**
`npm run db:reset` ในเครื่องจะเห็นคำใหม่ แต่ฐานข้อมูลบนคลาวด์ยังใช้คำเก่า
แล้วเครื่องกับของจริงจะไม่ตรงกันโดยไม่มีใครรู้

→ ต้องเพิ่ม **migration ใหม่** ที่ `create or replace` ทั้งสามฟังก์ชัน

## Decisions — ตัดสินแล้ว

### 1. คำที่ใช้แทน

| เดิม | ใหม่ |
| --- | --- |
| ก๊วน (การนัดเล่นครั้งหนึ่ง) | **นัด** |
| ก๊วนของฉัน | **นัดของฉัน** |
| หาก๊วน | **หานัด** |
| สร้างก๊วน · จัดการก๊วน | **สร้างนัด · จัดการนัด** |
| ใบเสร็จก๊วน | **ใบเสร็จนัด** |

### 2. คำว่า "ผู้จัดก๊วน" ต้องหายไป ไม่ใช่แค่เปลี่ยนคำต่อท้าย

ใช้ **"ผู้จัด"** เปล่า ๆ ตรงที่บริบทชัด และ **"ผู้จัดนัด"** ตรงที่ต้องขยาย

เหตุผล: LSN-0026 จะเพิ่ม `group_members.role = 'owner'` ซึ่งคือ *เจ้าของก๊วน*
ถ้าปล่อยคำว่า "ผู้จัดก๊วน" ไว้ มันจะกลายเป็นชื่อของอีกบทบาทหนึ่งทันที
รวมถึง `display_name` ใน seed ที่เขียนว่า "ก้อง ผู้จัดก๊วน"

### 3. ชื่อนัดตัวอย่างใน seed → เปลี่ยนด้วย

`'ก๊วนแบดเย็นวันพุธ'` → `'แบดเย็นวันพุธ'` เพราะในโลกจริงผู้ใช้ตั้งชื่อนัด
ไม่ได้เอาคำว่านัดมานำหน้า และ seed คือสิ่งที่คนในทีมเห็นบ่อยที่สุด

### 4. ไม่ทำ automated guard กันคำเก่ากลับมา

เคยคิดจะเพิ่มเทสที่ห้ามคำว่า "ก๊วน" ใน `src/` แต่**ทำไม่ได้** เพราะ LSN-0026
จะใช้คำนั้นอย่างถูกต้องสำหรับกลุ่มคน เทสแบบนั้นจะต้องถูกถอดทันทีในตั๋วถัดไป
ซึ่งแย่กว่าไม่มีเลย → อาศัย review ของตั๋วนี้ และบันทึกไว้ตรงนี้ว่าเป็นการตัดสินใจ
ไม่ใช่การลืม

### 5. AC ของ LSN-0023 จะกลายเป็นเท็จ และต้องบันทึกไว้

LSN-0023 (done แล้ว) มี acceptance criteria ข้อหนึ่งเขียนว่า

> คำที่ใช้: **"ใบเสร็จก๊วน"** · "ค้าง" · "จ่ายแล้ว" — ห้ามใช้คำว่า invoice

ตั๋วนี้เปลี่ยนคำนั้นเป็น "ใบเสร็จนัด" → ต้องไปเขียนหมายเหตุในตั๋ว LSN-0023
ว่าคำถูกเปลี่ยนโดยตั๋วนี้ **ไม่ใช่แก้ AC ของตั๋วที่ปิดแล้วให้ดูเหมือนไม่เคยมีอะไรเกิดขึ้น**
ส่วน "ห้ามใช้คำว่า invoice" ยังมีผลอยู่

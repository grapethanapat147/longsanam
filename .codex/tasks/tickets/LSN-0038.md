# 🟢 LSN-0038 — ปุ่มจัดทัวร์นาเมนต์ครั้งถัดไป

**Type:** Feature · **Phase:** 10 · **Status:** Done
**Source:** เกรพขอโดยตรง 18 ก.ย. 2569
**Depends on:** LSN-0032 (หน้าสร้างทัวร์นาเมนต์) — merge แล้ว

## Goal

เจ้าภาพเปิดงานครั้งถัดไปได้โดย **ไม่ต้องกรอกค่าที่เหมือนเดิมใหม่ทั้งหมด**

## Context

งานประจำจะจัดซ้ำด้วยค่าเดิมเกือบทั้งหมด — ก๊วนเจ้าภาพ รุ่น ค่าสมัคร ขั้นต่ำ/สูงสุดทีม
มีแต่ **วันเวลา** ที่ต้องเปลี่ยนแน่นอน ตอนนี้ต้องกรอกใหม่ทุกช่องทุกครั้ง

หน้าก๊วนมีปุ่มตั้งนัดใหม่ที่ผูกก๊วนให้แล้ว (`/organizer/new?groupId=…`) แต่ฝั่ง
ทัวร์นาเมนต์ยังไม่มีอะไรแบบนั้นเลย

## Scope

- ปุ่มบนหน้ารายละเอียดทัวร์นาเมนต์ **เฉพาะเจ้าภาพ** ไปที่ `/app/tournaments/new?from=<id>`
- หน้าสร้างอ่านงานต้นทางแล้วเติมค่าให้ล่วงหน้า
- **ไม่เติมวันเวลา** — วันของงานเก่าอยู่ในอดีต การคัดลอกมาจะได้งานที่ผิดกติกาทันที
  (`registration_deadline <= starts_at` และวันแข่งที่ผ่านไปแล้ว) ปล่อยว่างบังคับให้เลือกใหม่

## Non-goals

- ไม่คัดลอกทีมที่สมัคร ผลแมตช์ หรือการจ่ายเงิน — งานใหม่คืองานใหม่
- ไม่เดาชื่อรายการให้ (เช่นเติม "ครั้งที่ 2" เอง) — ชื่อคัดลอกมาตรง ๆ ให้แก้เอง
  เพราะรูปแบบชื่อของแต่ละคนไม่เหมือนกัน การเดาจะผิดบ่อยกว่าถูก
- ไม่แตะ RPC ฝั่งฐานข้อมูล ไม่มี migration

## Acceptance Criteria

- [x] เจ้าภาพเห็นปุ่มบนหน้างานของตัวเอง
- [x] คนที่ไม่ใช่เจ้าภาพ **ไม่เห็นปุ่ม** เพราะสร้างงานในนามก๊วนนั้นไม่ได้อยู่แล้ว
- [x] กดแล้วฟอร์มมีค่าเดิมครบ: ก๊วนเจ้าภาพ · ชื่อ · รุ่น · ค่าสมัคร · ขั้นต่ำ · สูงสุด
- [x] **ช่องวันเวลาว่างทั้งสามช่อง**
- [x] เข้าลิงก์ `?from=` ของงานที่ตัวเองไม่มีสิทธิ์อ่าน ต้องไม่ระเบิด — ตกกลับเป็นฟอร์มเปล่า
- [x] เข้าหน้าสร้างแบบไม่มี `?from=` ยังทำงานเหมือนเดิมทุกอย่าง
- [x] เทสเดิมเขียวทั้งหมด

### ตรวจของจริง

| เจ้าภาพ (ก้อง) เห็นปุ่ม | เห็น ลิงก์ `/app/tournaments/new?from=aaaaaaaa-…-0001` ป้าย "จัดครั้งถัดไป" |
| คนที่ไม่ใช่เจ้าภาพ (บอส) | **ไม่เห็นปุ่ม** — เจอโดยบังเอิญตอนล็อกอินค้างเป็นบอส เลยได้พิสูจน์ข้อนี้ไปในตัว |
| ค่าที่คัดลอกมา | ก๊วน "แบดเย็นลาดพร้าว" · ชื่อ "ศึกแบดลาดพร้าว ครั้งที่ 1" · รุ่น P · ฿800 · ขั้นต่ำ 4 · สูงสุด 8 |
| ช่องวันเวลา | **ว่างทั้งสามช่อง** ตามที่ตั้งใจ |
| `?from=` ของ id ที่อ่านไม่ได้ | ฟอร์มเปล่า ค่า default ปกติ ไม่ระเบิด |

### สองอย่างที่ตั้งใจไม่ทำ

**ไม่เติมวันเวลา** — วันของงานเก่าอยู่ในอดีต ถ้าคัดลอกมาจะได้ฟอร์มที่ผิดกติกาของตาราง
ตั้งแต่ยังไม่ทันแตะ (`ends_at > starts_at` ผ่าน แต่วันแข่งที่ผ่านไปแล้วไม่มีความหมาย)
แล้วผู้ใช้ต้องมานั่งหาว่าผิดตรงไหน ปล่อยว่างบังคับให้เลือกใหม่ตรงไปตรงมากว่า

**ไม่เดาชื่อให้** — เกรพขอปุ่มชื่อ "จัดทัวร์นาเมนต์ครั้งที่ 2" แต่การไปเติม "ครั้งที่ 2"
ในชื่อรายการเองจะผิดบ่อยกว่าถูก เพราะรูปแบบชื่อของแต่ละคนไม่เหมือนกัน
("ครั้งที่ 1" · "2026" · "รอบฤดูฝน") คัดลอกตรง ๆ แล้วให้แก้หนึ่งช่องชัดเจนกว่า
ป้ายปุ่มจึงเป็น "จัดครั้งถัดไป" ซึ่งจริงกับสิ่งที่มันทำ
